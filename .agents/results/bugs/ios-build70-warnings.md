## 원인과 수정

- React Native 0.86의 미리 빌드된 React 프레임워크를 Swift가 가져올 때 CocoaPods가 같은 이름의 소스 헤더를 먼저 찾았음. Clang은 프레임워크 안의 헤더가 포함되지 않았다고 각 파일마다 보고함. 소스·프레임워크에서 이름이 겹치는 헤더 278개가 기기·시뮬레이터 슬라이스에서 각각 바이트 단위로 같았음. 동일한 arm64 Clang 가져오기 검사에서 검색 순서만 바꿨을 때 경고 294건이 28건으로 줄었음. Podfile에서 해당 프레임워크에 의존하는 Swift Pod만 현재 플랫폼용 헤더를 우선하도록 수정함. 세 개 Pod만 수정한 중간 빌드에서는 ExpoSecureStore에서 다시 294건이 나타나 의존성 기준으로 범위를 확정함.
- expo-file-system 57.0.1의 레거시 전송 델리게이트 헤더 4개가 일부 포인터와 콜백의 nil 허용 여부를 생략했음. 기존 postinstall에서 선언을 보완함. 전송 성공 시 nil인 오류와 생략 가능한 진행 콜백·작업 관리자를 허용함. 기본 초기화 시의 블록 프로퍼티와 응답 인자의 기존 미지정 계약을 보존함.
- 같은 패키지의 업로드 조회·진행 알림에 잘못된 작업 타입 2곳이 있었음. 업로드 클래스 확인을 통과한 객체 반환 타입과 업로드 전용 델리게이트가 콜백에 전달하는 타입을 맞춤. 빌드 70 원시 로그에 두 경고 모두 있었음.
- 빌드 70에 남은 주요 경고에는 SQLite 정수 축소 110건, 기호 없는 오브젝트 파일 38건, Hermes 번들 전역 이름 34건, SVG 상위 메서드 호출 경고 26건이 있음. 이번 변경은 경고 차단 플래그·의존성 버전 변경을 추가하지 않음.

## 검증

- 엄격한 iPhone Clang 검사에서 원본 전송 헤더와 업로드 구현 두 곳의 실패를 재현하고, 수정 후 nil 성공·진행 콜백 호출이 컴파일됨을 확인함. 잠금 파일의 해시와 일치하는 패키지 원본에서도 헤더 패치를 재적용했고 두 번째 postinstall에서 변경이 없었음.
- CocoaPods 설치, iOS 네이티브 모듈 통합 검사, 빌드 66 회귀 검사, git diff --check 통과. 설치된 Pods 검사에 Debug·Release 헤더 순서와 실제 Objective-C 구현 컴파일을 포함함.
- Expo 전송 구현 5개를 원본 헤더·구현과 수정 헤더·구현으로 각각 arm64 iOS 16.4, Apple Clang `-Os` 컴파일함. 5개 모두 어셈블리 출력이 바이트 단위로 같았음.
- React에 남은 28개 헤더는 프레임워크의 공개 umbrella 헤더가 직접 열거하지 않은 파일임. 검사에서 경고를 계속 표시하며 공개 API 범위를 임의로 넓히지 않음.
- 새 DerivedData로 로컬 Xcode 27.2 무서명 iPhone Release 아카이브 성공. 오류 0건, XCResult 전체 경고 661건, React 헤더 28건. Expo 전송 헤더 34곳과 업로드 타입 2곳 모두 원시 로그에서 0건. SDK와 컴파일러가 다른 Cloud 27.1의 전체 경고 감소량은 미확인. 로컬 아카이브는 검증용 서비스 설정을 사용했고 배포하지 않았음.
- 원본 Cloud 로그와 XCResult는 다운로드 폴더, 검증 결과는 /tmp/weatheron-warning70/clean.xcresult에 보관함. 커밋·푸시·새 Cloud 빌드·수정본 실기기 재검증은 수행하지 않았음.
