# WeatherON Project Wind 이미지 검토 및 재제작 프롬프트

검토일: 2026-09-12

## 1. 결론과 확인 범위

현재 4장은 분위기 탐색용 초안으로는 쓸 수 있으나, 실제 앱 적용 기준안으로 승인하기에는 수정 필요함. 메뉴 오류, 테마별 구조 불일치, 실제 데이터에 없는 풍향, 홈 목적지 준비 기능 축소가 우선 문제임.

프로젝트에 저장된 최종 PNG 4장을 직접 열어 확인했고, 현재 로컬 소스의 메뉴·화면·데이터 타입과 Project Wind 무드보드 및 v1.0/v1.1 문서를 대조했음. 앱 코드는 변경하지 않았음. 설치된 앱의 빌드·렌더링·터치·스크린리더를 검증한 결과는 아님. 현재 작업 트리의 코디·옷장 관련 수정도 건드리지 않았음.

검토 대상:

- A: `weatheron-home-light.png`
- B: `weatheron-home-dark.png`
- C: `weatheron-weather-wind.png`
- D: `weatheron-departure.png`

Project Wind의 스마트홈·일정·환기·종합 점수 실험은 WeatherON 기능으로 간주하지 않음. 이번 사용자 요구가 해당 실험 문서보다 우선함.

## 3. 화면별 검토

### A. 홈 라이트

유지할 점: 기온·상태·준비 문장이 잘 읽힘. 최종 수정본에서는 초기 버전에 있던 근거 없는 지도 선이 제거됐음. 원근 없는 단일 화면 형식도 맞음.

수정할 점:

1. 현재 `흐림` 텍스트에 비 내리는 큰 아이콘이 붙어 있어 현재 강수와 오후 예보가 혼동됨. 현재는 구름 아이콘, 오후 비는 시간별 영역과 준비 문장으로 분리해야 함.
2. 오른쪽 아래 우상향 막대는 시간·단위·수치가 없어 무슨 데이터인지 알 수 없음. 근거 없는 장식 그래프 제거 필요.
3. 큰 날씨 패널과 큰 코디·시계 일러스트가 목적지 관련 기능 공간을 차지함. 텍스트 크기를 줄이기보다 비어 있는 면적과 아이콘 크기부터 줄이는 게 적절함.
4. 실제 홈의 `오늘의 목적지` 선택·추가, 목적지 강수, 목적지 준비물, 우산 추천 진입이 빠져 있음. 출발 시각만으로 대체할 수 없음.
5. 현재 홈에는 독립된 시간별 예보 행이 없고 히어로를 눌러 H6으로 이동함. 홈 AmbientTimeline은 이번 요청에 따른 의도적인 정보 재배치이며, 기존 구현을 그대로 재현한 것은 아님.
6. `15:30 출발 · 비 오기 전 여유 있게`는 15시 비 예보와 충돌함. `이동 시간대 비 예보 · 우산 준비`처럼 근거 있는 문구로 수정 필요.
7. 작은 청회색 보조 글자·골드 탭 글자의 대비는 별도 측정 필요. 선명한 본문과 달리 부수 정보가 흐려 보임.

복원 권장 순서: 위치·알림 → 현재 날씨와 한 줄 준비 → 오늘의 목적지와 이동 판단 → 시간별 예보 → 코디 요약. 홈 목적지 강수는 **현재 값**, 시간별 강수확률은 **해당 시각 예보**임을 명시해야 함.

근거: `apps/mobile/src/screens/HomeScreen.tsx:63`, `:146`, `:187`, `:224`, `:248`.

### B. 홈 다크

유지할 점: 주요 흰 글자와 네이비 배경의 위계는 읽기 쉬움. 기온·최고최저 값은 A와 같음.

수정할 점:

1. A는 하단 요약 2열, B는 세로 2행임. 패널 높이, 제목 위치, 문장 크기, 아이콘, 상단 버튼, 예보 카드 구조, 탭 선택 장식도 다름. 같은 화면의 테마 비교로 사용할 수 없음.
2. 사진 같은 구름·빗줄기·패널 전체 명암이 무광 재질보다 폭풍 장면에 가까움. 현재 `흐림`과도 맞지 않음.
3. 밤 아이콘을 쓰지는 않았지만 어두운 폭풍 장면 때문에 테마 변경과 날씨 변화가 섞여 보임. A의 동일한 낮 구름 아이콘을 유지해야 함.
4. 우산·코디·출발 아이콘까지 골드가 확장돼 주요 행동·선택 상태 한정 원칙이 약해짐.
5. 배경·카드·테두리의 단계가 A와 다름. A를 기준 원본으로 고정한 뒤 색과 명도만 교체하는 편집 방식 필요.

### C. 날씨 상세 — 바람과 시간별 변화

유지할 점: 풍속 숫자와 한국어 설명을 우선했고, 링을 종합 점수로 만들지 않았음. 공기질 없음 상태도 명시했음.

수정할 점:

1. 제목은 `날씨 상세`, 위치와 업데이트 시각도 표시해야 함. 현재 제목은 `날씨`뿐임.
2. 하단 탭과 홈 활성 상태 누락됨.
3. 앱 공통 `WeatherSnapshot.current`에는 `windMs`만 있고 풍향 필드 없음. 현재 모바일·공유·서버 소스에서 풍향 식별자도 확인되지 않음. `남서풍`과 방향 바늘은 현재 앱에서 표시할 수 있는 연동 정보가 아님.
4. 현재 적용 기준안에는 `바람 4.2 m/s · 풍향 정보 없음`을 표시하고 방향 바늘·유동 방향을 제거해야 함. 풍향 예시가 필요한 별도 연구안에만 합의된 샘플 풍향을 쓰고, 데이터 연동이 필요한 항목임을 화면 밖에서 밝혀야 함.
5. Project Wind 실험 매핑에서 4.2 m/s는 slow 범위임. `바람이 약간 강하게 불고 있어요`를 자동 붙일 근거는 부족함. 숫자를 우선하고 검증되지 않은 위험 판단을 추가하지 않는 편이 적절함.
6. 기존 H6의 현재 기온·체감·현재 강수·자외선·주간 예보가 사라짐. 바람 영역 확대를 위해 모두 제거하면 전체 날씨 상세 화면 역할을 잃음. 현재 날씨 요약은 위에, 주간 예보는 스크롤 아래에 보존 가능함.
7. H6은 Android/web에서 미세먼지·초미세먼지를 개별 표시하고 iOS에서는 대기질 패널을 숨김. C의 단일 공기질 카드는 이번 요구에 따른 신규 표시 제안으로 구분해야 함. 대기질 통합 점수나 실내 공기질로 바꾸면 안 됨.
8. A/B 12·13시 구름 아이콘이 C에서는 해+구름으로 달라짐. 공통 샘플 상태로 통일 필요.
9. `오늘 4월 26일 (토)`는 지정되지 않은 날짜임. 임의 생성된 날짜 제거 필요.
10. 강수확률 제목이 수치와 같은 줄에 끼어들어 시간별 5열과 정렬이 어긋남. 제목을 별도 행으로 옮기고 시간·아이콘·기온·강수확률을 같은 5열 중심에 맞춰야 함.
11. 습도 카드의 `현재 습도`, 공기질 카드의 반복된 없음 설명과 하단 바람 안내는 면적 대비 정보량이 낮음. 중복 설명을 줄이면 기존 지표·주간 예보를 살릴 공간이 생김.

### D. 출발 — 목적지 케어

유지할 점: 목적지·시각·이동수단·예상시간이 명확함. 15:30 + 35분 = 16:05 계산은 맞음. `자세히` 구조와 한 번만 있는 지도 CTA, 가상 지도·경로 후보 미노출은 적절함.

수정할 점:

1. G1 출발 목록이 아니라 G2 목적지 상세임을 상단과 뒤로가기로 명확히 해야 함.
2. 실제 출발지, 출발/도착 시간 기준 변경, 이동수단 변경의 조작 단서가 없음. 현재 화면은 조회용 정보표처럼 보임.
3. 선택한 시각인지 계산된 추천 출발 시각인지 구분되지 않음. 샘플은 `출발 시간 15:30`을 사용자가 지정했고 `16:05 도착 예정`은 예상 이동시간으로 계산한 것으로 고정하는 편이 명확함.
4. 케어 켜짐/꺼짐, iOS 자동 카운트다운 상태, 목적지 코디가 이미지에 없음. 기본 화면에는 짧은 상태 및 요약으로 복원할 필요 있음.
5. 반복 요일·알림 기준·준비 여유·현재 위치/목적지 날씨 비교·알림 설정은 실제로 `자세히` 안에 있음. 정적 이미지로는 보존 여부를 알 수 없으므로 재제작 프롬프트에 펼침 내용 계약을 명시해야 함. 전부 기본 화면에 펼치는 것은 권장하지 않음.
6. 저장 목적지 삭제·복구 흐름과 장소 분위기 이미지도 현재 구현에 있음. 삭제 기능은 상세 하단에 남기고, 장소 이미지는 이번 차분한 요약 목적에 따라 작게 하거나 생략 가능함. 기능 누락과 장식 생략은 다르게 취급해야 함.
7. 이동시간의 신뢰 상태가 없음. 예상값·경로 확인 전 상태를 짧게 표시해야 함. 실제 소스는 `routeOptions`가 있을 때 실제 대중교통 경로를 보여주는 분기도 있음. 이를 근거로 이번 샘플에서 경로 후보를 창작할 수는 없음.
8. 현재 지도 버튼 문구는 국내 `카카오맵 길찾기`, 해외 `Google 지도 길찾기`임. 이번 요청의 `지도 앱에서 길찾기`로 통일하는 것은 의도적인 카피 변경 제안임. 버튼 개수 1개는 유지 가능함.
9. `16시부터 비`와 홈 15시 비 아이콘이 충돌하고, 지역도 명시되지 않아 같은 예보인지 구분하기 어려움. 이번 샘플에서는 `목적지 15~16시 비 예보 · 우산 준비`로 일치시켜야 함.
10. 거대한 4행 정보 카드, 안내를 감싼 중첩 카드, 크게 빛나는 골드 버튼은 정보보다 포장 면적이 큼. 2~3줄 요약과 얇은 구분선, 높이 52~56pt의 무광 버튼으로 줄일 여지 있음.
11. 출발 탭 아이콘이 A/B의 자동차와 D의 핀으로 바뀜. 실제 앱의 동일한 출발 아이콘 계열로 통일해야 함.

## 4. 화면 전체의 발전 방향

- 무광 정체성: 흐린 필터보다 매끄러운 불투명 표면, 낮은 채도, 미세한 명도 단계, 얇은 테두리로 구현함. 본문과 숫자는 선명하게 유지함.
- 데이터 밀도: 예보 5열 아래 동일 높이의 작은 패턴 영역을 두고 확률에만 연결함. 예를 들어 20·30·45·60·70%가 같은 척도에서 다른 밀도로 나타나게 하되 숫자도 함께 유지함. 패턴에 새로운 종합 의미를 붙이지 않음.
- Quiet Signal: 골드는 주 CTA와 선택된 탭·목적지에만 사용함. 날씨·코디·미선택 아이콘은 네이비/청회색으로 유지함.
- 타이포그래피: 실제 프로젝트의 Pretendard 기준 계열을 우선함. 390×844pt에서 본문 16pt, 보조 13~14pt, 제목 20~24pt, 기온 64~72pt를 재제작 목표로 제안함. 전부 굵게 만들지 않음.
- 아이콘: 일관된 선 굵기·크기·모서리 사용. 사진풍 구름·납작한 그림·굵은 삽화를 섞지 않음. 선택 상태에서만 채움 여부를 바꿀 수 있음.
- 안전 영역: 1170×2532px는 390×844pt의 3배 출력으로 설계함. 예시 상단 47pt·하단 34pt를 확보하고 44pt 터치 목표는 출력 기준 132px로 판단함. 숫자만 1170px로 키운다고 읽기 쉬워지는 것은 아님.
- 상태 구분: 정상·로딩·오래된 데이터·정보 없음·권한 필요를 같은 정상 스타일로 꾸미지 않음. 단, 정상 상태 시안에 모든 오류를 동시에 넣을 필요는 없음.
- 범위 구분: 코디 C1, MY M1, 출발 목록 G1 시안은 이번 A~D 요청에 포함되지 않았으므로 이미지가 없는 것 자체는 제작 누락이 아님. 다만 전체 앱 시각 방향까지 승인하려면 후속 검토 필요함. 코디 탭 자체가 빠진 것은 명백한 오류임.

## 5. 해상도 및 검증 정정

저장된 최종 PNG는 모두 1170×2532px임. 그러나 4장 생성 원본은 모두 853×1844px이고, 이후 확대 처리됐음. 따라서 고해상도 네이티브 렌더 원본으로 볼 수 없음. 앞선 완료 안내에서 이 차이를 설명하지 않은 점 보완 필요함.

재제작에서는 A를 확정한 뒤 A를 참조 편집해 B를 제작하는 방식이 적절함. 단순히 같은 프롬프트를 독립 실행하면 구조가 바뀔 수 있음. 정확한 한글·정렬·테마 동일성·출력 품질이 필요한 최종 전달본은 실제 텍스트와 컴포넌트로 정리한 뒤 해당 해상도로 출력하는 단계가 유리함. 이번 요청은 검토와 프롬프트 작성이므로 추가 생성·앱 구현은 진행하지 않았음.

접근성 대비 수치, 실제 터치 영역, 큰 글씨 재배치, 스크롤·뒤로가기·알림·외부 지도 동작은 PNG만으로 통과 판정할 수 없음.

## 6. 재제작용 프롬프트

아래 공통 프롬프트와 해당 화면 지시를 함께 사용함. A부터 제작하고 승인된 A를 B의 편집 대상으로, C/D의 재질·타입 기준으로 사용함. 기존 결과 이미지는 오류가 있는 비교 자료이며 메뉴·날씨 상태의 정답 기준으로 쓰지 않음.

### C — 날씨 상세

```text
A의 서체·여백·재질·아이콘을 기준으로 C 날씨 상세 라이트를 제작한다. 홈에서 들어온 상세 화면이며 하단 홈 탭이 활성이다.

하단 홈 · 코디 · 출발 · MY, 홈 활성. 내부 컴포넌트명이나 설명용 가짜 라벨은 표시하지 않는다.
```

풍향을 보는 연구용 추가 변형이 꼭 필요할 때만 C 지시의 풍향 부분을 다음으로 교체함. 현재 앱 적용 가능안과 구분해 파일·캡션에서 관리하며 화면에 가짜 기능 라벨을 넣지는 않음.

```text
이 이미지는 풍향 연동 이후를 가정한 별도 디자인 연구안이다. 명시적으로 제공된 샘플 풍향 225°, 남서풍을 사용한다. “남서풍 4.2 m/s”, “남서쪽에서 불어와요”를 함께 표시한다. 링의 표식은 바람이 불어오는 남서쪽을 나타내며, 흐르는 방향을 나타내는 화살표와 혼동하지 않게 한다. 종합 점수·진행률은 없다. 이 샘플이 현재 앱의 실제 풍향 데이터라고 주장하지 않는다.
```

### D — 목적지 케어

```text
A와 같은 라이트 재질로 D 목적지 케어 상세를 제작한다. 출발 탭의 목적지 목록 자체를 대체하지 않는다.

상단: 뒤로가기와 “홍대입구역”. 뒤로가기는 출발 목록으로 돌아가는 구조다. 주소는 “서울 마포구 양화로”를 작은 보조 텍스트로 표시한다.

첫 판단 영역: “16:05 도착 예정”을 우선 표시하고 “15:30 출발 · 대중교통 · 예상 35분”을 함께 둔다. 이 시각은 사용자가 출발 시간을 지정한 상태다. “실제 경로 확인 전”, “케어 꺼짐”을 짧은 텍스트로 유지한다.

조작 가능한 요약 행: “출발지 · 현재 위치”, “출발 시간 · 15:30”, “이동수단 · 대중교통”. 각각 변경 가능한 화살표나 편집 단서를 둔다. 조작 영역 최소 44pt를 확보한다. 시간 변경 시 출발 기준과 도착 기준을 선택할 수 있는 기존 흐름을 보존한다.

준비 안내: “목적지 현재 18° · 흐림 · 강수확률 20%”, 그 아래 “이동 시간대에 비 예보가 있어요. 우산을 챙기세요.”. 필요하면 “목적지 15시 60% · 16시 70%”를 짧게 보조한다. 현재 강수와 미래 예보를 섞지 않는다.

“자세히”는 닫힌 상태이며 “예상 35분 · 목적지 현재 강수 20%”를 요약으로 보여준다. 펼치면 현재 위치/목적지 비교, 준비 여유, 반복 요일, 알림 기준·설정, 케어 변경을 볼 수 있는 구조다. 이 항목들을 기본 화면에 모두 펼쳐 넣지는 않는다.

iOS 샘플: “자동 카운트다운 · 케어 꺼짐”을 작은 상태 행으로 표시한다. 케어가 꺼진 상태에서 예약 완료나 실행 중으로 꾸미지 않는다.

목적지 코디는 “얇은 재킷과 방수 신발 추천” 한 줄 요약을 유지한다. 저장 목적지 삭제는 스크롤 아래의 보조 동작으로 남기는 구조다. 큰 장소 사진과 장식 지도는 사용하지 않는다.

주요 버튼은 “지도 앱에서 길찾기” 하나만 둔다. 높이 52~56pt, 절제된 무광 골드 배경에 네이비 글자. 지도 버튼을 자세히 안팎에 중복하지 않는다. 경로 후보·노선명·지도 선·도보 구간·구간별 날씨를 창작하지 않는다.

하단 홈 · 코디 · 출발 · MY, 출발 활성. 같은 출발 아이콘을 사용하고 본문·버튼이 하단 독과 겹치지 않게 한다.
```

## 7. 재제작 완료 판정

- 네 화면의 탭 개수·명칭·순서·아이콘이 동일하고 활성 탭이 올바른가.
- A/B를 겹쳐 비교했을 때 색 이외에 위치·크기·줄바꿈·상태가 바뀌지 않았는가.
- 현재 흐림과 오후 비를 구분했고, 모든 시간대의 숫자·아이콘이 일치하는가.
- 홈 목적지 선택·추가·강수·준비물·코디 진입이 보이는가.
- C의 주간 예보·자외선·하단 메뉴가 보존됐고 풍향이 연동된 것처럼 위장되지 않았는가.
- D가 목적지 상세이며 시간 기준·추정 상태·케어 상태·변경 동작이 읽히는가.
- 경로·종합 점수·미지원 측정값·임의 날짜가 생성되지 않았는가.
- 실제 생성 해상도와 최종 파일 해상도를 모두 확인했는가.
- PNG 검토와 실제 기기 접근성·동작 검증을 혼동하지 않았는가.
