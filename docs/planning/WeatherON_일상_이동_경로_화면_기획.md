# WeatherON 일상 이동 경로·날씨 화면 기획

> 기준일: 2026-09-08
> 상태: G2 요약·국내 카카오 대중교통 상세·외부 길찾기 1차 구현. 실기기 검증·출시 완료를 의미하지 않는다.
> 출시 범위는 [기능 출시 로드맵](WeatherON_기능_출시_로드맵.md), 시각 규칙은 [UI 디자인 스펙](../design/WeatherON_UI_Design_Spec.md)을 따른다.

## 1. 목표와 범위

목적지까지 얼마나 걸리고 언제 나가야 하는지 WeatherON 안에서 판단하게 한다. 실제 경로를 알 수 있을 때는 노선·환승·도보 단계를 함께 제공하고, 알 수 없는 값은 만들지 않는다.

- 국내 대중교통: 기존 카카오맵 REST 응답의 실제 후보를 최대 3개까지 `자세히`에서 보여준다. 가장 빠른 실제 후보의 시간을 출발 판단에 사용하고 노선·환승·요금·도보 단계를 표시한다.
- 해외: Google Distance Matrix의 시간·거리 요약만 현재 범위다. 노선·환승·도보 단계·복수 후보는 Google Routes API 승인·비용·약관 검토 전 제공하지 않는다.
- 제외: 앱 내부 음성 안내, 상시 GPS 추적, 이탈 감지·자동 재탐색, 승하차 감지, 실시간 버스 도착 보장, 비를 피하는 경로 자동 생성.
- 자동차·도보는 기존 선택과 외부 길찾기를 유지한다. 해외·도시 간 복합 이동은 공급 범위 검증 전 내부 경로 조회 대상으로 약속하지 않는다.
- 여행 코스·GPX·WCI는 기존 `출발 → 여행 → 도보 코스` 범위다. 통근·통학 경로 조회를 여행 생성이나 구독으로 연결하지 않는다.

## 2. 단순한 기본 경험

사용자는 경로 기능을 설정하지 않아도 출발 판단을 얻어야 한다. 기본 흐름은 `목적지 상세 열기 → 출발 시각·날씨 확인 → 필요하면 길찾기`다. 새 경로 선택을 필수 단계로 추가하지 않는다.

- 기존 출발지·시간 기준·이동수단을 재사용한다. 시간 기준은 `도착 시간` 또는 `출발 시간` 중 하나만 선택한다. 출발지가 없으면 현재 위치를 사용할 수 있는 경우에만 사용하며, 권한이 없으면 직접 장소를 선택한다. 임의 좌표나 시각으로 확정형 출발·도착 시각을 만들지 않는다.
- 대중교통을 고르면 G2 안에서 가장 빠른 실제 경로의 시간과 날씨 요약을 보여준다. 후보 상세는 같은 화면의 `자세히`에서 확인하며 비교 화면으로 이동하지 않는다.
- 최초에는 출발지·이동수단·날짜·도착 조건에 맞는 유효한 후보 중 공급자 추천 첫 경로를 `추천 경로 기준`으로 미리 보여준다. 미리보기만으로 목적지 저장·계정 연결·알림 설정을 실행하지 않는다.
- 이미 적용한 경로가 있으면 이를 우선 재확인한다. 운행 변경·소멸 시 다른 경로로 알림 기준을 조용히 바꾸지 않고 변경 필요 상태를 표시한다.
- 기본 화면에는 출발 시각, 이동 요약, 준비 안내만 우선 표시한다. 여유시간 계산·환승 상세·알림 근거는 요약 영역의 `자세히` 안에 둔다. 데이터 미확인·오래된 값·알림 갱신 실패 등 행동 판단에 필요한 상태는 접지 않는다.
- WeatherON 안의 출발·도착 판단과 국내 대중교통 상세 확인이 기본 완료 흐름이다. `카카오맵/Google Maps에서 상세 경로 보기`는 지도 확인이 필요할 때 쓰는 보조 버튼으로 두고 외부 앱/웹 이동임을 표시한다.

### 기본 입력과 조회 시점

- 출발지와 시간 요약은 각각 눌러 수정한다. 기존 시간 시트 안에서 `도착 시간/출발 시간` 기준과 시각을 함께 고르고, 별도 설정 화면은 만들지 않는다. 이동수단 시트는 재사용하고 출발지 직접 선택은 기존 장소 검색을 활용한다.
- 출발지가 없으면 목적지 날씨를 먼저 보여주고 `출발지 선택`을 안내한다. 출발지만 있고 도착 목표가 없으면 지금 출발 기준 예상 이동시간·도착 시각을 보여주고 `도착 시간 설정`을 선택 사항으로 둔다. 목표가 없을 때 권장 출발 시각을 만들지 않는다.
- 저장한 반복 일정은 다음 실제 발생 날짜를 표시한다. 사용자가 지정한 일회성 목표가 지났으면 다음 날로 몰래 바꾸지 않고 선택 기준에 따라 `출발 시간 변경` 또는 `도착 시간 변경`을 제공한다.
- G2 첫 진입 시 유효한 입력이 있을 때 조회한다. 입력 확정 때 다시 조회하고 시트 열기·상세 펼침·단순 렌더링은 조회 사유가 아니다.
- G2에 머무는 동안 결과가 만료되면 `경로 다시 확인`을 표시한다. 자동 재탐색은 하지 않는다. 유효기간은 공급자 PoC에서 정하며, 확정 전 실제 운영에 노출하지 않는다.
- `자동`은 가장 빠른 교통수단을 비교한 결과로 표현하지 않는다. 내부 경로 조회 초기 범위는 명시적으로 대중교통을 선택한 경우이며, 자동·도보·자차는 기존 동작과 외부 연결을 유지한다.

## 3. 화면별 배치

### G1 목적지 목록

기존 3줄 요약을 유지한다. 새 필터·지도·경로 버튼은 추가하지 않는다. 큰 글씨에서는 높이를 늘려 필수 정보를 보존한다.

```text
회사                                  상세 >
목적지 24° · 현재 위치보다 2° 낮음 · 비 예상
08:12 출발 · 09:00 도착 목표
```

출발 시간 기준이면 `08:12 출발 · 예상 09:00 도착`으로 같은 3줄 안에서 표시한다.

수치는 설명용이다. 목록 카드마다 경로 API를 자동 호출하지 않는다.

### G2 목적지 상세 — 한 화면에서 판단 완료

기존 도착·이동 선택 시트를 재사용한 현재 1차 구현 구조다.

```text
< 회사
[집 출발 ▾] [도착 09:00 ▾] [대중교통 ▾]

08:12 출발 권장
[대중교통 ▾] 지하철 38분
추천 경로 기준
목적지 현재 비 예상 · 우산 챙기세요
자세히 ▾

[카카오맵에서 상세 경로 보기]
목적지 날씨 비교 / 기존 알림 설정
```

- 출발지·시간 기준은 각각의 요약을 눌러 수정한다. 시간 시트에서 `도착 09:00`과 `출발 08:12` 중 한 기준을 선택한다. P1 목적지 추가에서 새 경로 조건을 필수로 요구하지 않는다.
- 대중교통 선택 즉시 시트를 닫고 같은 화면에서 결과를 갱신한다. 기본 선택에 버스·지하철·혼합 질문을 연달아 띄우지 않는다.
- 주요 수치 옆 계산식과 별도 경로 카드를 늘리지 않는다. 상세를 열지 않아도 언제 나가고 무엇을 챙길지 알 수 있어야 한다.
- 장소 이미지는 축소하거나 핵심 판단 아래에 둔다. 날씨를 이유로 코디·우산 카드를 경로 요약 안에 중복 추가하지 않는다.
- 실제 경로가 없으면 후보와 구간 타임라인을 노출하지 않는다. 추정 소요시간은 추정임을 표시한다.
- 하단 탭과 기존 G2 라우트는 유지한다. 여행 미출시 상태에서 여행 전환 탭도 추가하지 않는다.

### 실제 대중교통 경로 — `자세히` 안의 조회 결과

```text
가장 빠른 경로       38분 · 환승 1회
지하철 · 1,550원
도보 6분 · 620m
2호선 · 성수역 → 을지로입구역

대안 2              43분 · 환승 0회
버스 · 1,500원
```

- 카카오 응답의 유효한 후보를 소요시간순 최대 3개 표시한다. 첫 후보를 출발 계산 기준으로 사용하며 후보 선택 상태는 만들지 않는다.
- 각 후보에는 실제 이동시간·거리·환승 횟수·요금과 도보/버스/지하철 단계를 표시한다. 단계에는 공급자가 준 안내·노선·첫/마지막 정류장을 사용한다.
- 공급자가 주지 않은 배차 시각·구간별 도착 시각·실시간 혼잡도는 만들지 않는다.
- 버스·지하철·혼합 세부 필터는 추가하지 않는다. 현재 API에 선택 필터 입력이 없고, 입력만 늘려 결과 차이를 보장할 수 없기 때문이다.

### 자세히 — 같은 화면에서 펼치는 근거

별도 이동 날씨 화면을 만들지 않는다. G2의 요약 아래에 실제 후보 카드를 펼치며 접어도 스크롤 문맥을 유지한다.

- 예상 이동시간·준비 여유와 실제 도보 → 탑승 → 환승 → 도보 순서의 구간·노선을 표시한다.
- 도보 구간은 시간·거리, 탑승 구간은 노선·승하차 지점 중심으로 압축한다. 실제 경로 시각이 없으므로 목적지 날씨를 도보 구간 날씨로 붙이지 않는다.
- 첫 구현에는 지도 표시를 넣지 않는다. 타임라인만으로 구간 위치를 이해하기 어렵다는 사용성 결과가 나오면 검토한다.
- 도보시간은 비 노출시간이 아니다. 지하 통로·지붕 정보 없이 `비 안 맞는 길`, `비 노출 9분`을 표시하지 않는다.
- 향후 구간 예보를 추가할 때는 분 단위 경로와 시간 단위 예보 해상도를 구분하고, 공급자 결정 전에는 보류한다.

## 4. 상태와 복귀 규칙

| 상황 | 표시·동작 |
|---|---|
| 첫 경로 조회 | G2 이동 요약 영역 로딩, 중복 요청 방지. 화면 전체를 막지 않음 |
| 재조회 | 기존 결과에 `다시 확인 중` 표시. 새 결과 확인 전 적용 불가. 이미 저장된 선택을 다른 경로로 자동 교체하지 않음 |
| API 실패·쿼터 초과 | `경로를 불러오지 못했어요` + 재시도·외부 길찾기. 가짜 노선 생성 금지 |
| 운행 없음·지원 지역 밖 | `현재 조건의 경로를 확인할 수 없어요` + 시각 변경·외부 길찾기 |
| 위치 권한 거부 | 출발지 직접 검색 허용. 경로 조회를 위해 상시 위치 권한 요구 금지 |
| 경로 없음·만료 | 확정형 출발 권장 시각 대신 `경로 확인 전`. 기존 추정치 사용 시 추정임을 명시 |
| 경로 성공·날씨 실패 | 경로는 유지하고 구간 날씨만 `날씨 확인 전`. 목적지 예보로 구간 예보를 위장하지 않음 |
| 예보 범위 밖 일정 | `예보 대기`. 경로 제공 가능 여부는 별도 판단 |
| 목표 시각 도달 불가 | `도착 목표를 맞추기 어려워요` + 시각 변경. 과거 출발 시각을 지금 출발 권장으로 표현하지 않음 |
| 출발 시각 직접 지정 | 선택 시각을 출발 예정으로 표시. 이동시간이 있으면 예상 도착을 계산하고, 없으면 `도착 시간은 경로 확인 후` 표시 |
| 외부 앱 미설치·열기 실패 | 지원되는 웹 길찾기, 실패 시 주소 복사. 원래 선택·입력 보존 |
| 지도 앱에서 돌아옴 | 이동 완료나 경로 일치를 가정하지 않는다. G2 상태 유지, 재조회는 명시적 액션으로 제공 |

경로 조건이 바뀌면 이전 요청의 늦은 응답이 새 선택을 덮어쓰지 않아야 한다. 경로 변경 후 이전 경로의 날씨는 새 결과로 교체될 때까지 `날씨 확인 중`으로 전환한다. 날씨 실패는 길찾기를 막지 않는다.

### 미리보기·저장·알림의 액션 기준

| 액션 | 화면·저장·알림 반영 |
|---|---|
| 기본 추천 미리보기 | G2 표시와 구간 날씨만 갱신. G1 저장 카드·기존 알림은 변경하지 않음 |
| Guest/미저장 목적지에서 경로 적용 | 현재 G2에서만 사용. 로그인이나 저장을 자동 시작하지 않음 |
| 계정 연결된 저장 목적지에서 경로 적용 | 목적지 경로 선호를 저장하고 G1 계산 기준을 갱신. 기존 출발 알림이 켜져 있으면 지원되는 일정의 예약 갱신도 요청 |
| 현재 추천으로 목적지 저장 | 별도 경로 선택 없이 현재 기준을 저장. 계정 연결이 필요하면 입력을 보존해 복귀. 알림은 자동으로 켜지 않음 |
| 기존 알림 설정에서 ON/변경 | 현재 기준 경로와 일정으로 요청. 필요한 계정·권한 흐름 이후 복귀하며 별도 경로 선택을 요구하지 않음 |
| 시트 임시 선택·필터 변경·취소 | 저장·알림 변경 없음 |

- 저장 실패는 `저장하지 못했어요`와 재시도를 제공한다. G1에는 기존 저장값을 유지하고 G2의 변경값은 미저장 상태로 표시한다.
- 미리보기와 예약 기준이 다르면 기존 알림 영역에 실제 예약 시각을 표시한다. 새 화면의 출발 시각이 곧 알림 예약 시각인 것처럼 보여주지 않는다. 추가 확인 팝업은 만들지 않는다.
- 예약 갱신은 동일 목적지·일정의 기존 예약을 교체하는 방식으로 검증한다. 실패 시 `출발 알림 업데이트 필요`를 접지 않고 표시하고 실제 확인된 예약 상태만 알린다. 기존 예약 취소 여부를 확인할 수 없으면 `예약 상태 확인 필요`로 표시한다. 재시도로 중복 예약을 생성하지 않는다.
- 반복 일정은 저장한 수단·노선 선호를 바탕으로 다음 발생 건의 경로를 재검증해야 한다. 앱 미실행 시 재검증·예약 갱신까지 검증된 경우에만 경로 기반 반복 알림을 활성화한다. 그 전에는 기존 알림 기준을 유지·표시하고 새 경로 시각으로 매일 알린다고 약속하지 않는다.

## 5. 데이터·시간·권한 경계

- 경로 판단에는 출발/도착 좌표, 선택한 시간 기준·날짜·시각·시간대, 실제 수단, 노선, 환승, 도보시간, 구간 시각, 조회 시각이 필요하다. 자동 기본 날짜를 화면에 보여주고 자정 경계와 다음 날 이동을 구분한다.
- 도착 목표 기반 검색이 가능한 공급자인지 검증한다. 지원하지 않으면 현재 이동시간을 단순 역산한 `예상 출발`로 한정하며 미래 배차를 반영했다고 표시하지 않는다.
- 시간표 기반 경로에서는 공급자 출발·도착 시각을 존중하고 여유시간은 준비 여유로 별도 표시한다. 여유시간을 뺐다고 더 이른 열차가 보장되는 것은 아니다.
- 목적지별 이동수단·선호 조건과 일시적인 경로 조회 결과를 구분한다. 매일 동일한 버스·열차와 시각이 유효하다고 재사용하지 않는다. 결과 저장 기간은 공급자 약관 확인 후 정한다.
- 기존 DestinationCare와 목적지 일정 상태에 카카오 상세 후보를 저장한다. 원본 경로 좌표는 저장하지 않고 화면에 필요한 단계 정보만 보존한다.
- Guest는 경로 조회·현재 화면 적용·외부 길찾기 가능, 지속 저장·동기화는 기존 계정 연결을 따른다. 알림 신청 때 계정·알림 권한을 확인하고 원래 액션으로 복귀한다. 경로 조회 자체에 로그인·구독을 요구하지 않는다.
- 외부 지도 연결은 국내 카카오맵, 해외 Google Maps로 지역별 기본 연결 하나를 제공하고, 별도 지도 앱 선택 설정은 추가하지 않는다. 수단을 넘길 수 없으면 다른 수단으로 몰래 대체하지 않고 외부 지도에서 확인하도록 안내한다.
- 외부 앱으로는 지원되는 출발지·목적지·이동수단만 전달한다. 선택 노선·도착 목표의 전달 가능 여부는 별도 검증한다. `지도 앱에서 경로가 달라질 수 있어요`를 연결 버튼 근처에 짧게 표시한다.

## 6. 구현 전 검토와 출시 순서

| 단계 | 산출물 | 다음 단계 조건 |
|---|---|---|
| 화면 기획 | 본 문서·공통 문서 정합 | 정보 구조와 실패/복귀 상태 정의 |
| 정적 목업 | G2 기본/입력 누락/상세 펼침, 선택 시트/빈 결과, 예보 실패·알림 불일치 | 작은 화면·큰 글씨에서 핵심 정보 확인, 실제 사용성 검토 |
| 외부 연결 | G2에서 지도 앱/웹 연결 | iOS·Android 설치/미설치/복귀 검증 |
| 국내 상세 응답 | 카카오맵 대중교통 후보·환승·요금·단계 표시 | 실계정 API와 실기기에서 응답·쿼터·운행 종료·미지원 지역 검증 |
| 해외 상세 경로 | Google Routes 비용·약관·키 승인 후 별도 구현 | 해외 도시별 노선 품질과 시간 기준 검증 |

국내 상세와 외부 연결은 코드 기준 1차 구현했지만 실계정 API·출시 빌드·실기기 검증을 의미하지 않는다. TMAP·ODsay 등 신규 공급자는 이번 범위에서 검토하거나 도입하지 않는다.

## 7. 화면 검증 체크리스트

- 처음 보는 사용자가 선택한 출발/도착 기준, 계산된 반대편 시각, 예상 이동시간을 구분할 수 있는가.
- 기존 목적지 상세에서 추가 선택 0회로 출발 시각·준비 안내를 확인할 수 있는가(유효한 입력·데이터 기준).
- 대중교통 선택 시 화면 전환·추가 질문 없이 결과가 나오는가.
- 처음 보는 사용자 5명 중 4명 이상이 기본 화면에서 5초 안에 나갈 시각과 준비물을 찾는가. 이는 목업 검증 목표이며 측정 결과가 아니다.
- 경로 비교와 상세 펼침을 쓰지 않아도 기본 흐름이 완료되는가.
- 필터 변경·조건 변경·뒤로가기에서 적용 전 값이 저장된 값을 덮어쓰지 않는가.
- 후보 없음과 조회 실패가 구분되고, 모든 상태에서 복귀 또는 대안 행동이 있는가.
- 응답의 네 번째 이후 후보도 필터 조건에 맞으면 표시되는가. 필터로 현재 선택이 가려졌을 때 잘못 적용되지 않는가.
- 첫 추천에도 날씨 요약이 나오고, 새 경로에 이전 날씨가 남지 않는가.
- 출발지 없음·시간 기준 없음·지난 출발/도착 목표·다음 반복 일정이 구분되는가.
- Guest 적용은 로그인 없이 끝나고 미리보기만으로 G1·알림이 바뀌지 않는가. 저장/예약 실패 상태가 실제 상태와 일치하는가.
- 큰 글씨에서도 노선·시각·CTA가 잘리지 않으며 고정 버튼이 본문을 가리지 않는가.
- 터치 영역은 iOS 최소 44pt, Android 최소 48dp이고 선택 상태는 색 외 텍스트/체크로도 구분되는가.
- VoiceOver/TalkBack에서 경로 수단·소요시간·환승·선택 상태를 읽고 화면 복귀 시 초점이 돌아오는가.
- 지도 없이도 정보를 이해할 수 있고 모션 감소 설정을 존중하는가.
- 외부 연결 후 동일 경로·도착·승하차가 확인된 것처럼 처리하지 않는가.

## 8. 검토 및 보완 이력

2026-09-08 검토에서 다음을 보완했다. 정적 문서 검토이며 사용성 테스트 통과를 의미하지 않는다.

- 최초 추천에는 날씨가 없을 수 있던 조회 기준을 현재 표시 경로 하나로 통일했다.
- 출발지·도착 목표 누락, 자동 수단, 조회 시점과 만료 처리 기준을 추가했다.
- 후보 제한보다 필터를 먼저 적용하고, 숨겨진 선택·단일 후보 상태를 정의했다.
- Guest 적용·지속 저장·알림 갱신을 분리하고 실제 예약과 미리보기 불일치를 표시하도록 했다.
- 반복 알림은 앱 미실행 시 다음 일정 재검증을 별도 출시 조건으로 두었다.

## 9. 공급자 검토 출처

2026-09-08 검토에 사용한 공식 문서다. 기능 존재 확인과 WeatherON 계약/국내 품질 검증은 별개다.

- [카카오맵 REST API](https://developers.kakao.com/docs/ko/kakaomap/rest-api): 국내 대중교통·도보 경로 상세 응답 확장 기준.
- [카카오맵 URL Scheme](https://apis.map.kakao.com/ios_v2/docs/getting-started/urlscheme/): 출발지·목적지·이동수단을 지정한 외부 길찾기.
- [Google Routes 대중교통](https://developers.google.com/maps/documentation/routes/transit-route): 해외 경로 확장 기준. 국내에는 적용하지 않는다.
