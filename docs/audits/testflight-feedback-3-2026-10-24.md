## 판정

문구 고정 버그는 제공 자료·코드 검사·후속 실기기 검사에서 재현되지 않음. 확인한 목적지·시간 변경 흐름에서는 온도 구간에 따라 문구가 정상 갱신됨. 원인이 확인되지 않아 동작 코드는 수정하지 않음.

첨부 화면은 현재 위치 16°C / 체감 16°C, 목적지 도착 무렵 10/25 10:00 예보 17°C임. `HomeScreen`은 `destinationCare.destinationWeather`와 목적지 도착 시각을 `buildHomePreparation`에 전달함. 상단 현재 위치 기온과 준비 문구의 목적지·시각 기준이 다름. 해당 화면의 17°C와 문구는 코드 기준으로 일치함.

강수·강풍 안내가 우선하며, 해당 신호가 없을 때 온도 기준은 다음과 같음.

| 기준 온도 | 문구 |
| --- | --- |
| 5°C 이하 | 포근한 겉옷으로 따뜻하게 나가요 |
| 5°C 초과–18°C 이하 | 가볍게 걸칠 한 겹, 같이 챙겨 나가요 |
| 18°C 초과–30°C 미만 | 편한 차림으로, 기분 좋게 나가요 |
| 30°C 이상 | 물 한 병 챙기고, 여유롭게 나가요 |

선택 시각 예보가 없으면 목적지 현재 체감/기온으로 전환하고 그 기준을 표시함. 오래됐거나 신뢰할 수 없는 데이터에는 중립 안내를 표시함. 같은 온도 구간에서는 문구가 같음.

## 변경 및 검증

동작 코드는 변경하지 않음. `scripts/check-home-outing.mjs`에 이 피드백의 온도별 회귀검사를 추가함.

- WeatherKit/Open-Meteo에서 -10, 0, 5, 5.01, 17, 18, 18.01, 25, 29.99, 30, 40°C의 실제 준비 함수 결과 확인.
- 목적지 도착 예보가 같으면 현재 기온이 바뀌어도 준비 문구를 유지하는지 확인.
- 목적지 예보 온도가 바뀌면 각 온도 구간의 문구가 나오는지 확인.
- 섭씨/화씨 표시 변경에도 판단이 같은지 확인.
- 선택 시각 예보가 없을 때 현재 기준으로 전환하는지 확인.
- NaN/무한대 온도에서 옷차림을 단정하지 않는지 확인.
- 기존 강수·눈·바람 우선순위, 데이터 누락·오래됨·목적지 없음 검사도 통과함.

검증 명령: `node --no-warnings scripts/check-home-outing.mjs`.
추가로 모바일 TypeScript 검사(`tsc --noEmit -p apps/mobile/tsconfig.json`)와 `git diff --check` 통과함.
