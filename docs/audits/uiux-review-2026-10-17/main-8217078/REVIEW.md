승인된 Ambient 방향은 유지하는 편이 적절함. 개선의 첫 순서는 검색 결과의 관련성, 수치의 신뢰 여부, 안내가 가리키는 시간 범위를 일치시키는 것임. 아래의 P1은 출시 전 우선 수정 제안, P2는 후속 사용성·시각 정리임. 전체 앱이나 출시 준비도의 점수는 매기지 않음.

## 우선 개선

### 1. P1 — 목적지 검색에서 입력 의도보다 거리가 앞섬

**직접 확인:** `서울역` 입력 시 첫 결과가 `서울특별시청 서울역일대종합발전기획단`, 다음 결과들이 시청 인근 업체임. 검색어와 직접 관련 없는 결과까지 상단에 섞이고 일부 업체에 `산` 분류도 표시됨. 원하는 역을 찾기 위해 결과를 더 탐색해야 함.

**코드 근거:** [placeSearchRanking.ts:19](/Users/daehyeonchoi/Claude/Projects/스마트 날씨 앱/apps/mobile/src/utils/placeSearchRanking.ts:19). 위치가 있으면 거리 차이를 먼저 비교하고, 이름 일치 순위는 거리 동률에서만 사용함. 공급자 원본 결과 자체의 누락·분류 오류 여부는 별도 확인 필요함.

**개선:** 검색어 입력 시 정확 일치 → 이름 관련성 → 같은 관련성 안에서 거리 순으로 정렬 제안함. 주변 추천은 기존 거리 우선 유지함. 업체 분류를 실제 공급자 카테고리와 대조하고 불확실한 값은 숨김.

**완료 기준:** 서울역·시청역·동명이름·해외 대표 장소 검색에서 정확한 장소가 상단에 오고, 가까운 무관 업체가 이를 밀어내지 않아야 함. 공급자 후보에 없는 결과를 임의 생성하면 안 됨.

근거 이미지: [검색 결과](./search-390.png).

### 2. P1 — 날씨 상세에서 누락값·이전 자료를 실제 관측값처럼 읽을 위험

**코드 확인:** 상세의 현재 기온·체감·바람은 가용성 플래그 확인 없이 수치로 렌더함. WeatherKit 어댑터는 값 누락 시 fallback 수치와 `tempAvailable`, `feelsLikeAvailable`, `windAvailable`를 함께 제공함. 홈·코디의 신뢰 안내에 비해 상세는 출처 상태를 식별하기 어려움. 정상 날씨 화면에서 실제 누락 상황을 재현한 것은 아님.

**근거:** [WeatherDetailScreen.tsx:105](/Users/daehyeonchoi/Claude/Projects/스마트 날씨 앱/apps/mobile/src/screens/WeatherDetailScreen.tsx:105), [weatherKitAdapter.ts:36](/Users/daehyeonchoi/Claude/Projects/스마트 날씨 앱/packages/shared/src/weather/weatherKitAdapter.ts:36).

**개선:** 실제 0과 누락을 구분하고 누락은 `—` 또는 `확인 중` 표시함. 이전 자료는 관측 시각·`최근 관측`을 함께 표시함. 상태 설명 옆에 재시도 동작 제공 제안함.

**완료 기준:** 실제 0°C·0m/s는 유지하고, 플래그가 false인 fallback 0은 관측값처럼 표시하지 않아야 함. 홈→상세에서 자료 신뢰 상태가 일치해야 함.

### 3. P1 — 시간별 예보 요약과 펼쳐진 예보 범위가 다름

**직접 확인:** 상세에 `07:00 강수 60%` 요약이 나오지만 표시된 카드들은 12:00부터 시작하고, 12:00~23:00의 값은 0~30%임. 요약에는 날짜가 없어 이미 지난 시간인지 다음 날인지 알기 어려움.

**코드 근거:** [WeatherDetailScreen.tsx:43](/Users/daehyeonchoi/Claude/Projects/스마트 날씨 앱/apps/mobile/src/screens/WeatherDetailScreen.tsx:43), [WeatherDetailScreen.tsx:135](/Users/daehyeonchoi/Claude/Projects/스마트 날씨 앱/apps/mobile/src/screens/WeatherDetailScreen.tsx:135). 요약은 전체 hourly에서 첫 강수 시점을 찾고, 카드는 앞 12개만 표시함.

**개선:** 요약과 카드에 같은 시간 범위 사용함. 범위 밖 비 소식을 알려야 한다면 `내일 07:00 비 가능`처럼 날짜를 붙이고 해당 예보로 이동할 수 있게 함. 가로 목록 끝에 다음 시간이 더 있다는 시각 단서도 유지함.

**완료 기준:** 요약의 시간·확률을 같은 화면에서 찾을 수 있거나 명시적인 이동 경로가 있어야 함. 과거·오늘·내일 및 위치 시간대가 구분돼야 함.

근거 이미지: [날씨 상세](./weather-detail-390.png).

### 4. P2 — iOS에 개선된 코디 기준이 다른 플랫폼에는 남아 있음

**직접 확인:** 최신 웹 홈에서 `맑음·강수 0%`, 코디에서 `비가 세요`와 레인부츠가 함께 나옴. 현재 날씨와 미래 예보가 다를 수 있으므로 숫자 차이 자체보다 언제 비가 오는지 설명이 없는 점이 문제임.

**코드 근거:** [useWeatherOnAppState.ts:663](/Users/daehyeonchoi/Claude/Projects/스마트 날씨 앱/apps/mobile/src/state/useWeatherOnAppState.ts:663). 오늘 남은 시간 범위와 관측 상태를 다루는 buildTodayOutfit은 iOS에만 적용됨. Android 실기기에서 재현한 것은 아님.

**개선:** 플랫폼별 시각 표현은 유지하면서 추천의 시간 범위·위치·신뢰 안내 기준을 맞추는 방향 제안함. `현재 맑음 / 오늘 저녁 비 예보`처럼 현재와 미래를 분리함.

**완료 기준:** 같은 입력에서 플랫폼별 준비물 안내의 의미가 일치해야 함. iOS에 이미 들어간 개선을 미해결 문제로 취급하지 않음.

근거 이미지: [홈](./home-390.png), [코디](./outfit-390.png).

### 6. P2 — 코디 확인 실패 후 화면 안에서 복구하기 어려움

**코드 확인:** 최신 iOS 코디는 최근 자료·온도 미확인 안내를 제공하지만 현재 화면에는 날씨를 다시 확인하는 동작이 없음. 사용자에게 확인을 요구하면서 실제 행동은 홈 등 다른 경로에서 찾아야 함.

**근거:** [OutfitScreen.tsx:19](/Users/daehyeonchoi/Claude/Projects/스마트 날씨 앱/apps/mobile/src/screens/OutfitScreen.tsx:19), [OutfitScreen.tsx:47](/Users/daehyeonchoi/Claude/Projects/스마트 날씨 앱/apps/mobile/src/screens/OutfitScreen.tsx:47).

### 8. P2 — 홈 문장 길이와 부가 설명의 위계 정리

**직접 확인:** 웹 390px에서 `오늘 날씨에 맞춰, 나갈 준비를 함께해요.`의 마지막 `요.`가 단독 줄로 내려감. 320px 홈은 가로 넘침 없었음. 큰 안내가 일반적인 인사 문구여서 실제 준비물보다 강조됨. iOS는 별도 preparation.copy를 사용하므로 같은 줄바꿈 문제로 단정하지 않음.

**개선:** 웹 문구를 `오늘 날씨에 맞춰 준비해요`처럼 짧게 줄임. 화면 전반에서 결론 한 줄→근거 한 줄→보조 상태 순으로 정리함. 승인된 Ambient 배경·아이콘은 유지하고 새 장식 추가는 후순위로 둠.

**완료 기준:** 320·390·430px와 큰 글자에서 한 글자짜리 고립 줄, 주 행동 가림, 정보 중첩이 없어야 함.

## 유지할 강점

- 홈에서 바로 위치 변경 가능해짐. 별도 설정을 찾는 이동을 줄였음.
- iOS 코디의 오늘 범위·온도 가용성·관측 상태 구분이 명확해짐. 새 디자인보다 이 계약을 다른 화면까지 일관되게 확장하는 편이 효과적임.
- 선택 시트에 닫기 버튼·헤더 드래그·취소 복귀·Reduce Motion 처리가 있음. Glass와 콘텐츠 알파를 분리한 구조도 유지할 가치 있음.
- iOS 공통 Ambient와 filled 아이콘을 승인된 방향으로 정리했으므로 화면마다 다른 스타일을 새로 도입할 필요 없음. 실제 기기 자연스러움은 별도 확인 대상임.

## 검증 범위와 한계

- `check-today-outfit`, `check-ios-selection-ui`, `check-home-outing` 통과함. 날짜 경계·누락값·선택 시트 동작 계약·강수 문맥 등의 회귀 근거이며, 네이티브 시각 PASS는 아님.

- impeccable context 실행은 엔진 캐시 권한/엔진 미설치로 실패함. 스킬 문서와 프로젝트 코드를 직접 읽는 fallback 사용함. 네이티브 검토 방법에 따라 웹 탐지기·오버레이·독립 A/B 평가는 적용하지 않음. 자동 품질 점수나 실기기 승인으로 표현하지 않음.
- 실행한 로컬 Metro 서버는 종료했고 브라우저 viewport 설정 복원 및 임시 탭 정리함. 별도 overlay 서버 실행 없음.
- npm 의존성은 저장소 lockfile 기준으로 복원하고 기존 postinstall 패치 적용함. package.json·lockfile 및 앱 소스 변경 없음.
- 질문 생략: 개선점 정리 요청이며 구현 방향 승인이 필요한 변경은 수행하지 않음.
