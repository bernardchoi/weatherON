## 1. 홈·출발 목록 강수 기준 통일 — P1

같은 선택 목적지가 홈에서는 `목적지 도착 무렵 · 10/18 10:00`, `강수확률 51%`로 표시됨. 출발 목록에서는 같은 출발·도착 시각 옆에 `우산 준비 · 82%`가 표시됨. 서로 다른 범위라는 설명이 없어 데이터가 바뀌거나 틀린 것처럼 읽힘.

[DestinationListScreen.tsx:478](</Users/daehyeonchoi/Claude/Projects/스마트 날씨 앱/apps/mobile/src/screens/DestinationListScreen.tsx:478>)에서 현재와 전체 hourly의 최대 강수 확률을 취함. iOS 요약도 이 값을 사용함. 목록 시간에는 날짜가 없어 `08:56 출발`이 오늘 지난 일정인지 내일 일정인지 구분하기도 어려움.

**개선:** 기존 도착 시점 예보 계산을 목록에서도 재사용함. 전체 예보 최고값을 남길 경우 `향후 예보 최대 82%`처럼 시간 범위를 별도로 명시함. 출발 시각에는 오늘·내일·요일 중 필요한 날짜 단서 추가함.

**완료 기준:** 같은 목적지·같은 일정·같은 자료에서 홈과 목록의 안내가 같은 의미여야 함. 도착 시각 예보가 없으면 다른 시간의 최고값으로 대신하지 않고 `해당 시간 예보 없음` 표시함.

증거: [홈](./review2-ios-home.png), [출발 목록](./review2-ios-destinations.png).

## 2. 상세에서 누락값과 관측값을 예보로 표시 — P1

정상 iPhone 화면에서는 23°C가 보였으며 누락 상태를 기기에 주입하지 않았음. 별도 재현 스크립트는 실제 WeatherKit 어댑터와 실제 화면 헬퍼를 실행함.

- 온도 없는 응답 → `tempAvailable=false`, `tempC=0`.
- hourly 없음 → `getHourlyForecast`가 현재 관측으로 카드 1개 생성함.
- 서울 관측 시각 `2026-10-17T03:00:00Z` → 시간 라벨 `03:00`, 실제 위치 시각 `12:00`.

[WeatherDetailScreen.tsx:105](</Users/daehyeonchoi/Claude/Projects/스마트 날씨 앱/apps/mobile/src/screens/WeatherDetailScreen.tsx:105>)는 가용성 플래그 없이 온도를 표시함. [같은 파일:368](</Users/daehyeonchoi/Claude/Projects/스마트 날씨 앱/apps/mobile/src/screens/WeatherDetailScreen.tsx:368>)은 관측값을 예보로 대체하며, `formatTimeLabel`은 UTC 문자열의 시각을 그대로 읽음. 강수 없음으로 대체된 값은 `강수 신호 낮음`까지 만들 수 있음.

**개선:** 현재 수치의 가용성·신선도 검사, 예보 없는 상태 명시, 관측 시각은 위치 시간대로 표시함. 관측값을 시간별 예보 카드로 만들지 않음.

**완료 기준:** 실제 0°C는 유지하고 누락 0은 `확인 중`으로 구별함. 예보가 없을 때 강수 낮음으로 단정하지 않아야 함. 정상 예보·빈 예보·누락 현재값·캐시 자료 각각 확인 필요함.

## 3. 검색 정렬은 서버 후보 수집부터 수정 — P1

iOS `searchPlaces`도 같은 검색 클라이언트를 사용함. [proxyCore.mjs:386](</Users/daehyeonchoi/Claude/Projects/스마트 날씨 앱/apps/server/src/proxyCore.mjs:386>)은 좌표가 있으면 Kakao 요청을 `sort=distance`로 보내고, 최대 2페이지 × 15건만 수집함. [placeSearchRanking.ts:19](</Users/daehyeonchoi/Claude/Projects/스마트 날씨 앱/apps/mobile/src/utils/placeSearchRanking.ts:19>)도 거리부터 비교함. 정확한 장소가 후보에서 빠지면 화면 정렬만 바꿔도 복구되지 않음.

추가 원인: [proxyCore.mjs:992](</Users/daehyeonchoi/Claude/Projects/스마트 날씨 앱/apps/server/src/proxyCore.mjs:992>)은 문자열의 `산` 포함 여부로 mountain을 지정함. 실제 함수에 `서비스,산업 > 여행사 모두투어 타조투어`를 넣으면 `mountain` 반환함. 공급자 카테고리의 `산업`까지 산으로 오인하는 구조임.

**개선:** 명시적 검색어가 있으면 공급자 관련성 기준으로 후보 수집하고, 이름 일치·관련성 안에서 거리 정렬함. 카테고리는 공급자 코드·구조화된 분류를 우선하고 불명확하면 일반 장소로 표시함.

**완료 기준:** 서울역·동명이름·해외 대표 장소에서 정확 후보가 확보되고 상단에 표시돼야 함. 산업·부동산 등 텍스트를 산으로 분류하지 않아야 함. 위치 없는 검색도 유지함.

**실기기 한계:** 검색 화면 진입은 성공했으나 미러링 타이핑·붙여넣기가 입력란에 반영되지 않아 iPhone 검색 결과 재현은 못 함. 웹 결과를 iOS 실기기 증거로 사용하지 않음.

## 4. 시간별 예보 요약에 날짜와 범위 표시 — P2

iPhone 날씨 상세에서 `05:00 강수 29%`가 요약으로 보이고, 시작 카드는 11:00~15:00·강수 0%였음. 날짜 없는 05:00만으로는 지난 시간과 다음 날을 구별하기 어려움.

[WeatherDetailScreen.tsx:43](</Users/daehyeonchoi/Claude/Projects/스마트 날씨 앱/apps/mobile/src/screens/WeatherDetailScreen.tsx:43>)은 전체 예보에서 첫 강수를 찾지만 카드는 앞 12개만 표시함. 29%가 표시되는 이유도 확률뿐 아니라 강수량 > 0 조건을 사용하기 때문이므로, 수치 자체를 오류라고 단정하지 않음.

**개선:** 같은 12시간 범위를 요약하거나 `내일 05:00 비 가능`과 해당 시간으로 이동하는 경로 제공함.

**완료 기준:** 요약 시점의 예보를 같은 화면에서 확인할 수 있어야 함. 오늘·내일·날짜 경계 설명이 일치해야 함.

증거: [iPhone 날씨 상세](./review2-ios-weather-detail.png).

## 6. 삭제 복구 시간 정책 통합 — P2

[DestinationListScreen.tsx:201](</Users/daehyeonchoi/Claude/Projects/스마트 날씨 앱/apps/mobile/src/screens/DestinationListScreen.tsx:201>)의 snackbar는 3.8초, [useWeatherOnAppState.ts:1778](</Users/daehyeonchoi/Claude/Projects/스마트 날씨 앱/apps/mobile/src/state/useWeatherOnAppState.ts:1778>)의 복구 상태는 4초 뒤 만료됨. 목록을 벗어나도 복구 상태가 지워짐. UI 시간을 늘려도 상태 타이머를 그대로 두면 복구 버튼이 사라지거나 효력이 없어짐.

**개선:** 복구 상태 수명을 한 곳에서 관리함. 복구 행동을 포함한 메시지는 읽고 조작할 시간을 보장하고, VoiceOver 탐색 중 만료되지 않게 함. 영구 보존 기능을 새로 만들 필요는 없음.

**완료 기준:** 메시지 낭독→버튼 이동→복구 가능한지 실제 VoiceOver로 확인함. 복구 시 장소·일정·알림 설정 보존 확인함. 이번에는 사용자 저장 목적지를 삭제하지 않았으므로 실제 삭제·복구 시험과 접근성 승인 수행 안 함.

## 7. 코디 실패 시 같은 화면에서 재시도 — P2

## 8. 코디 상세 이름·문구 정리 — P3

iPhone 코디 상세의 `오프화이트 캔버스 스니커즈`에서 마지막 `즈`가 단독 줄로 내려감. 3열 상세에서 긴 이름의 가독성이 떨어짐. `기본 중심의 규칙 기반 추천이에요. 보유 수는 날씨 적합도 점수가 아니에요.`는 사용자가 얻는 정보보다 구현 설명과 부정문이 앞섬.

**개선:** 3열 상품명을 의미 단위로 줄바꿈하거나 긴 이름에서 행 배치로 전환함. 문구는 `현재 날씨로 고른 3개 중 2개가 옷장에 있어요`처럼 기준·보유 의미를 직접 설명함.

**완료 기준:** 긴 한국어 이름과 큰 글자에서 한 글자 고립 줄·소유 상태 가림이 없어야 함.

증거: [iPhone 코디 상세](./review2-ios-outfit-detail.png).

## 유지할 부분

- iOS 홈이 현재 위치 날씨와 목적지 도착 무렵 안내를 구분함. 전체 구조를 바꾸기보다 다른 화면의 시간 기준을 맞추는 편이 효과적임.
- 코디의 `오늘 남은 시간 기준 · 관측 시각`과 현재 맑음에 맞는 안내 직접 확인함. 이전 웹의 `비가 세요` 지적을 iOS 문제로 유지하지 않음.
- 선택 시트의 체크 표시·닫기 버튼·목록 위계 확인함. 열기와 닫기 버튼 동작 성공함. Ambient 배경·Glass·filled 아이콘 방향 유지 제안함.

## 검증 및 남은 범위

- [재현 스크립트](./review2-repro.mjs) 통과: 실제 코드의 누락 온도·빈 예보 대체/UTC 라벨·산업 분류·iOS 지우기 조건을 확인하는 재현 검사임. 수정 완료를 뜻하는 PASS 아님.
- 실기기 기본 글자 크기·현재 테마에서 화면/탭 이동 확인함. 선택 시트 드래그는 미러링에서 닫힘을 확인 못 했으며 닫기 버튼으로 복귀함. 검색 입력도 미러링 전달이 실패함. 두 항목 모두 앱 결함으로 확정하거나 통과 처리하지 않음.
- VoiceOver·Dynamic Type·다크 모드·Reduce Motion·장시간 프레임 성능·삭제 복구·통신 실패·실제 알림 수신 미검증임. 접근성 전체 승인 보류함.
- iPhone 설치 앱의 빌드 해시 대조·신규 Xcode 빌드 수행 안 함. 코드 근거는 main, 화면 근거는 현재 설치 앱으로 구분함.
- 이전 웹 검토용 서버 종료함. iOS 실기기는 선택 변경 없이 홈 화면으로 복귀함.
