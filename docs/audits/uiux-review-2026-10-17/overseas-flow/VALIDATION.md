# 해외 목적지 저장·날씨·경로·알림 iOS 검증

## 검증 환경·데이터 보호

- 실제 iPhone 미러링과 로컬 Xcode Release 개발 서명 앱 사용함. 운영 API 사용함.
- 사용자에게 지피클럽 임시 삭제·설정 복원 허용받음. 기존 3개 한도 우회하지 않음.
- 기존 지피클럽: 회사 라벨, 케어 ON, 08:40 도착, 대중교통, 월~금 반복 ON, 강수 50%, 출발 60분 전 조건 기록함. [일정](./gp-before-plan.jpg), [알림](./gp-before-alert.jpg).
- 앱 DB 전체 추출 시도는 자동 승인 검토에서 사적 데이터 추출 위험으로 거절됨. 추출하지 않고 화면의 설정을 기록하는 방식으로 전환함.
- 파리 내 경로 검증에는 공개 장소인 Louvre Museum을 수동 출발지로 사용함. 종료 후 GPS 기준으로 복원 완료함.

## 확인한 실제 동작

- Eiffel Tower Google 검색 결과 실제 저장 성공함. 재실행 후 저장 목적지와 선택 유지됨.
- [목적지 목록](./eiffel-list-weather.jpg)에 France, 야간 맑음 약 9°C, 도착 10:05 무렵 약 11°C 표시됨. 같은 목록 국내 목적지는 약 24~25°C로 구분됨.
- 운영 WeatherKit의 파리 응답 좌표 48.86, 2.29, 현재 9.52°C, 야간, 시간별 예보 251개 확인함. 국내 날씨를 해외 이름으로 바꾼 값 아님.
- [수동 파리 출발지로 재실행한 홈](./paris-home-after-relaunch.jpg)에 Louvre Museum, 9°C, Eiffel Tower, 현지 도착 목표 및 출발 권장 유지됨.
- 한국→파리 경로는 fallback/국가 간 경로 확인 필요 반환함. 확정 이동시간·출발 시각으로 안내하지 않음.
- 루브르→에펠탑 실제 Google 경로: [자동/도로](./paris-driving-route.jpg) 15분+여유 15분, 10:05 도착에 09:35 출발 권장. [대중교통](./paris-transit-route.jpg) 선택 시각 기준 29분+여유 15분, 09:21 출발 권장.
- [실제 Google 지도 앱](./google-maps-paris-route.jpg)에서도 파리 경로, 대중교통 29분, GMT+2 표시 확인함.
- [운영 응답](./production.json)에 파리·도쿄 날씨, 한국→파리 미확인 경로, 파리 내 도로·대중교통 결과 기록함. 일본 대중교통 표본은 공급자가 ZERO_RESULTS 반환했으므로 실제 경로 성공으로 판정하지 않음.
- [알림 센터](./paris-scheduled-notifications.jpg)에서 파리 현지 07:30 아침 준비가 기기 시간 14:30, 현지 21:00 브리핑이 다음 날 기기 04:00으로 표시됨. 방해 줄이기 때문에 새벽 브리핑은 실제 예약 대상에서 제외됨.

## 발견 및 수정

1. 경로 없음 때문에 계산하지 못한 출발 시각을 ‘도착 시간 변경 필요’로 잘못 안내함. 목적지 현지 시각의 목표가 미래인지 별도 확인해 경로 미확인과 지난 시각 구분함. 해외 시간은 목적지 현지 시각 기준임을 표시함.
2. 목적지 예보 누락·오래된 예보·fallback에서 국내 또는 다른 목적지 예보로 목적지 알림을 예약할 수 있었음. 해당 예보의 목적지 예약 차단함. 정상 위치의 예보는 기존 예약 유지함.
3. GLOBAL은 국가 구분이 아니므로 GLOBAL끼리 같다는 이유로 fallback 이동시간을 사용할 수 없게 함. 실제 공급자 ready 경로만 출발 계산에 사용함.
4. 알림 센터가 설정·권한·방해금지·일일 제한 필터 전 후보까지 예정 건수에 표시함. 실제 예약과 같은 정책 함수 사용함.
5. Expo Constants 빌드 스크립트가 공백 경로에서 basename을 잘못 계산해 app.config 생성 건너뜀. 기존 postinstall 보정 스크립트에 경로 따옴표 수정 추가함. 실제 공백 경로 검사 통과함.
6. 이번 및 앞선 iOS 수정의 누락된 영어·일본어 문구 번역 보완함.
7. 수신 알림의 ‘보기’가 단순 Text여서 직접 탭해도 반응하지 않았음. 기존 onOpen을 실제 버튼에도 연결함. 최종 일반 앱에서 해당 버튼 직접 탭으로 에펠탑 상세 이동 확인함.

## 검사

- check-ios-uiux: 실제 화면의 시간 판정, 지난 출발 시각 유지, 센터 정책 필터, GLOBAL 추정 경로 차단, 공백 경로 Constants 생성 검사 포함해 통과함.
- check-shared-rules: 위치 미검증·stale·fallback 목적지 알림 차단 및 정상 목적지 예약 회귀 통과함. 기존 예약 검사의 잘못된 다른 장소 예보 재사용을 올바른 목적지 fixture로 수정함.
- 모바일 TypeScript, localization 2,234개 문구, git diff --check 통과함.

## 알림 및 최종 앱 실기기 결과

- 기존 QA 빌드 도구에서 목적지 확인 알림을 발송함. 전경에서 실제 Expo Notifications received 이벤트가 반영돼 [수신 확인됨](./notification-received.jpg) 확인함. 직접 수신 기록을 만들거나 기기 시각을 바꾸지 않음.
- [수신 알림함](./notification-inbox.jpg)에 새 알림 표시, [본문 탭](./notification-opened-eiffel.jpg)으로 Eiffel Tower 상세 이동 확인함.
- [최종 일반 앱의 보기 버튼 직접 탭](./notification-view-button-final.jpg)도 Eiffel Tower 상세로 이동함.
- [최종 예약 목록](./paris-scheduled-final.jpg)은 방해금지 시간인 기기 04:00 브리핑 제외, 파리 07:30에 해당하는 기기 14:30 아침 준비 한 개로 실제 예약 건수와 일치함.
- [국가 간 경로 미확인 안내](./international-route-fixed.jpg)는 미래 현지 도착 목표를 유지하고 ‘경로 확인 전’ 표시함. 임의의 국제 이동시간으로 출발 권장·알림 예약하지 않음.
- 최종 일반 앱 Xcode Release 빌드·개발 서명·덮어 설치·실행 성공함. app.config의 variant=platform, enableNotificationQaTools=false 검사 통과함.
- 시험용 Eiffel Tower 제거, GPS 기준 복원 완료함. 사용자 검색어 입력 후 용산구 원효로 152 지피클럽 재저장 완료함. 회사 라벨·케어 ON·08:40 도착·대중교통·월~금 반복 ON·강수 50%·출발 60분 전 복원 화면 확인함. [복원 일정](./gp-restored-plan.jpg), [복원 알림](./gp-restored-alert.jpg).

## 범위

- 실제 악천후를 만들거나 기기 시계를 바꾸지 않음. 파리 표본은 맑고 강수 0%여서 악천후 목적지 알림 미예약이 정상임.
- 첫 백그라운드 시험은 미러링 화면에서 시스템 배너를 확인하지 못함. 시스템 알림 센터 자동 접근도 응답하지 않아 OS 배너 탭은 검증되지 않음. 전경의 실제 네이티브 수신과 앱 알림함 이동 증거와 구분함.
- 장시간 백그라운드·앱 강제 종료 후 실제 악천후 자동 알림, APNs 서버 푸시, Xcode Cloud·TestFlight·App Store는 미검증임.
