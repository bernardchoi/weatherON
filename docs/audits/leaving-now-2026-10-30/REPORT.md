기준 HEAD: `53016f4eec2fd197e04daf71d06edc313bd65565`. d16ae98의 solver·초 단위 계산·캐시·저장 체계는 유지했음. 기존 미커밋 해외 경계/기기 시험 작업 위에 이번 변경만 추가했음. 이번 범위 패치는 [CHANGE.patch](./CHANGE.patch), 코드·웹·네이티브 해시는 [versions.json](./versions.json)에 있음. 커밋·push·배포·TestFlight 배포는 수행하지 않았음.

## 원인과 수정

기존 `resolveTravelTiming`은 전달받은 예정 경로의 `durationSeconds`에 `nowMs`를 더했음. 해당 소요시간이 과거 출발 조건인지 현재 출발 조건인지 확인하지 않았음. 앱 요청 effect는 예정시각이 지난 뒤에도 그 일정의 시각으로 조회하고 같은 저장 행을 갱신했음. 과거 자동차 요청이 서버에서 현재 교통으로 전환되는 경우도 있었지만, 도착 역산/시간대 예측/기존 캐시 응답 전체가 현재 출발 결과라는 보장은 없었음.

- 예정 계산에서 잘못된 `nowArrivalAt` 합산을 제거했음. `resolveTravelTiming`의 출발·도착·여유·준비 계산은 유지했음.
- 별도 `resolveLeavingNowTiming`만 현재 ETA를 계산함. `getDestinationLeavingNowTiming`이 일정의 예정 출발 경과 여부를 판단하고 하나의 표시 결과를 만듦. 홈·목적지 목록·상세·위젯이 이 결과를 공유함.
- 예정 출발이 지나면 동일 출발지/목적지/국가/이동수단으로 **선택 출발/도착시각을 보내지 않는 기존 요청 경로**를 사용함. 국내 자동차는 `/v1/directions` 현재 교통 API로 연결됨. 미래 운행/도착 역산 API를 새로 만들지 않았음.
- 서버는 `requestKind: now|scheduled`를 반환함. 기존 캐시 키가 선택시각 유무를 포함하므로 과거 예정 조회와 현재 조회의 캐시가 분리됨. 실패 시 stale의 원래 `updatedAt`·`expiresAt`을 유지함. 새로운 현재 조회처럼 시각을 만들지 않음.
- 공개 Kakao 대중교통/도보는 경로 소요시간 기준·시간대 미반영을 계속 표시함. Google 도보도 교통 반영으로 잘못 표현하지 않도록 수정했고, Google 대중교통은 현재시각 요청 및 운행·대기 확인 필요를 표시함. 배차·대기시간 가산은 추가하지 않았음.
- 현재 결과는 별도 메모리 상태에만 보관함. 저장 목적지, 목표시각, 반복 요일, 예정 경로, 알림·Live Activity 입력을 갱신하지 않음. 앱 재시작 시에는 다시 현재 조회하며, 오프라인 재시작에서 예정 경로를 현재 결과로 승격하지 않음.

공급자 시간 지원은 10/30 공식 명세를 재확인했음. Kakao 공개 대중교통/도보 요청에는 선택 출발시각 파라미터가 없으므로 시간 반영을 보장하지 않음([Kakao REST API](https://developers.kakao.com/docs/ko/kakaomap/rest-api)). Google의 출발시각 지원은 transit/driving에 한정되고 transit은 기본 now이므로 walking을 현재 교통 반영으로 표시하지 않음([Google Directions](https://developers.google.com/maps/documentation/directions/get-directions#departure_time)). 이는 명세에 따른 표시 한계이며 실제 이동 검증이 아님.

## 조회 상태·캐시·경합

| 상태 | 표시/계산 |
|---|---|
| 조회 중, 이전 현재 결과 없음 | 조회 중 + 도착 예상 확인 불가. 숫자를 만들지 않음 |
| 성공 | `now + 현재 소요 초`, 최신 조회, 원래 조회시각·공급자 근거 |
| 조회 중, 이전 현재 결과 있음 | 이전 조회 기준 참고 + 원래 조회의 ETA/조회시각 |
| 실패 또는 오프라인/연결 실패 | 실패 종류를 구분하고 사용 가능한 이전 **현재 조회**만 참고로 유지함 |
| 실패, 사용 가능한 이전 현재 결과 없음 | 도착 예상 확인 불가. 예정 40분/거리 추정으로 대체하지 않음 |
| 캐시 만료 | 참고 상태로 내림. 앱은 `expiresAt`에 한 번 갱신을 예약하며, WidgetKit도 같은 만료시각에 미리 전달한 동일 참고 문구를 선택함 |

현재 조회는 ready·공급자 검증·`requestKind=now`·선택시각 없음·현재/경로 근거·유효한 소요 초/조회·만료시각을 요구함. 거리 fallback이나 과거 일정의 결과는 이전 현재 값으로도 사용하지 않음. 참고 ETA는 원래 조회 출발시각 + 원래 소요시간에 고정되며, 현재시각을 계속 더해 새 결과처럼 움직이지 않음.

기존 1분/10분 재시도 제한과 서버 pending/cache를 재사용했음. 현재 조회는 1분 경로를 사용하고 서버 캐시는 기존 최대 1분 TTL임. 활성 앱에서만 조회함. 만료 타이머는 상태 변경을 한 번 알리고 기존 effect가 같은 제한으로 재조회함. 실패 반복은 분 주기/포그라운드 복구에서 제한적으로 재시도하며 즉시 무한 재시도하지 않음.

요청 effect cleanup으로 늦은 응답을 버림. 키는 출발·도착 ID/좌표/국가/수단을 포함하고 auto/drive를 정규화함. 상태는 최대 32개 문맥만 유지함. 빠른 설정 복귀에서 이전 loading 상태가 남는 문제도 함께 막았음. 응답 시각이 마지막 분 tick보다 새로워도 즉시 표시하도록 모든 현재 표시가 한 번의 현재시각을 사용함.

## 적용과 남은 경계

새 앱의 현재 조회에는 서버의 `requestKind`와 원래 조회/만료 메타데이터가 필요하므로 **서버를 먼저 적용해야 함**. 새 앱 + 구형 서버 조합은 현재 ETA를 확인 불가로 처리하며 과거 예정 소요시간으로 대체하지 않음. 새 서버의 추가 필드는 구형 앱이 무시할 수 있지만, 구형 앱의 잘못된 ‘지금 출발’ 계산 자체는 앱 업데이트 전까지 수정되지 않음. DB 마이그레이션은 추가하지 않았음.

로컬 Xcode 27.1 Release는 서명 없이 컴파일했음. 실기기 설치·Widget 렌더링·장기 백그라운드·실제 이동 오차는 이번 검사로 증명하지 않음. iOS 후보 실기기 검증은 Xcode Cloud → **내부 TestFlight만** 사용해야 함. 현재 작업에서는 원격 Worker 버전과 설치 빌드를 재조회하거나 배포하지 않았음.

내부 배포·복구 절차는 [기존 연결 검증의 적용 순서](../route-connection-2026-10-30/REPORT.md#내부-testflight-적용-순서호환성복구)를 따르되 이번 서버·앱 커밋/해시로 다시 고정해야 함. 새 서버 선적용 → Xcode Cloud 내부 전용 후보 → 아래 실기기 시험 순서임. 복구 시 Worker의 기록된 이전 version과 이전 내부 앱 조합으로 되돌리고 사용자 DB/App Group을 삭제하지 않음. 현재 ETA는 메모리 값이므로 앱 재실행 시 재조회함. 서버만 되돌리면 새 앱은 현재 ETA 확인 불가로 내림.

실제 WidgetKit 갱신 주기는 OS가 결정함. 만료시각 timeline entry를 넣고 그 entry의 날짜로 참고 문자열을 선택하지만, OS가 실제 화면에 그 시각에 반영하는지는 실기기 증거가 필요함. 현재 ETA를 알림·Live Activity에 새로 예약하지 않으므로 해당 표시는 예정 일정 기준을 유지해야 함.

시작 전 다른 작업의 미커밋 소스 변경을 보존했음. 소스에 대해 시작 시 diff의 역적용 `--check`를 통과했음. 다른 작업의 기기 시험 RUN_STATE 문서는 실행 중 추가 갱신됐으며 이번 수정에 포함하지 않았음. 전체 작업 트리를 이번 작업 변경분으로 간주하면 안 됨.

임시 localhost QA 서버와 IAB 탭을 종료했고 검증용 viewport 설정을 복원했음. `.env.local`은 수정하지 않았음.
