# iOS 사진·알림 안정화 검증

- 대상: iPhone 16 Pro Max / iOS 27.0 beta, 기존 설치 1.0.0 (35)
- 기준 코드: f265220 및 이번 알림 취소 확인 보완
- 범위: 사진 등록·재실행·앱 교체 후 보존, 삭제·복구·복구 안내 만료, 스마트 알림 끄기
- 해외 시간대 실기기 검증: 사용자 요청으로 제외
- 로컬 개발 빌드는 실기기 QA용이며 EAS/TestFlight 배포 검증과 구분함.

## 사전 데이터 보존

기존 Documents 백업 완료. 사진 메타데이터 2개와 JPEG 2개 존재 확인. 두 사진은 기존 보유 ID 목록에서 제외된 상태이며, 보유 프리셋은 17개였음. 사진 원본이나 개인 위치는 이 문서에 첨부하지 않음.

## 이번 보완

스마트 알림을 끈 직후 스위치 값만으로 '예약 0건'을 표시하던 동작 수정. 실제 iOS 예약 목록을 다시 읽어 0건인 경우에만 취소 성공 처리하며, 남아 있으면 확인 실패를 표시함. 개발 빌드에서는 취소 결과와 건수만 콘솔에 기록함.

## 남은 확인

사진 선택 후 남아 있던 등록·표시·사진 교체·삭제 및 즉시 복구 검증 완료. 기존 2개 사진은 테스트 전부터 보유 목록에서 삭제되어 있어 파일/메타데이터 보존만 확인했고, 새로 등록한 사진은 카드 표시까지 확인함. 복구 안내 자동 만료는 프리셋 공통 흐름으로, 사진 아이템은 즉시 복구 시 안내 제거로 검증함.

첫 `devicectl` 재실행에서 네이티브 시작 화면이 수십 초 유지되는 현상 1회 관찰. 로그를 연결한 재실행과 앱 덮어쓰기 후 실행, 프로세스 종료 후 홈 아이콘 실행에서는 정상 진입했음. 원인은 확정하지 못했으며 수정 완료로 간주하지 않음. production 빌드의 일반 실행 경로에서 재확인 필요.

이번 결과는 iOS 27 beta 기기 한 대의 로컬 Debug 검증임. EAS production/TestFlight 업데이트 설치 경로 및 장시간 백그라운드 실수신까지 통과한 것으로 해석하지 않음. TestFlight 업로드는 수행하지 않음.
