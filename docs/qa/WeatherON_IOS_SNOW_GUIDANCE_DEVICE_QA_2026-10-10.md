# iOS Home 강설 안내 수정·무선 실기기 확인 — 2026-10-10

## 시작 상태와 수정

브랜치 `feat/ambient-surface-foundation-home`, HEAD `6cea25ce5adacbdab154f45c1286e7462bd5c0fc`, 깨끗한 작업 트리에서 시작했다. 저장소 AGENTS.md, 이전 Home/배경 QA와 PRD F4 신발 룰(눈/한파 → 미끄럼 방지·보온 신발), 기술 ADR을 확인했다. 중복 xcodebuild/Metro는 없었다.

`buildHomePreparation`에서 강수확률 ≥50% 또는 강수량 >0을 곧바로 rainy로 묶고 눈보다 먼저 분기한 탓에, 실제 snow도 비·우산 안내가 됐다. 실제 함수를 호출하는 검사에 강설/확률/양/바람 조합을 먼저 추가했다. 수정 전 `snow 0%/1mm/2mps`에서 실제 출력 `비 소식이 있어요. 우산 하나 챙겨 나가요.`로 실패했다.

확인된 snow를 최우선으로 분기해 미끄럼 적은 신발을 안내한다. 강설+확인된 강풍도 눈·바람 문맥과 신발 안내를 유지한다. 현재 강설은 현재 문구, 도착 시각 예보는 예보 문구/기존 basis로 구분한다. 확인된 rain/storm은 기존 비·우산/방수 겉옷 안내를 유지한다. 형태 미확인 숫자 신호는 강수 가능성으로 표현하고 비나 눈을 단정하지 않는다. 숫자 evidence는 계속 중립적인 강수확률이며 기존 강수 링크 위치에 표시한다.

변경은 Home 준비 모델, EN/JA 5개 문구씩, 관련 회귀 검사뿐이다. 레이아웃·배경·유리 표면·아이콘 크기·글자 크기·H5 구현/문맥 전달·Android UI를 재설계하지 않았다. API/권한/패키지/비용 추가는 없다.

## 입력·설정 전환의 실제 제한

CUA로 iPhone Mirroring을 열고 연결을 시도했으나 `iPhone 사용 중 — 연결하려면 iPhone을 잠그십시오` 상태였다. 사용자에게 잠금 후 잠시 사용 중단을 요청했다. 개발 연결/스크린샷 가능 여부와 미러링 터치 입력 가능 여부는 별개다. 손가락/마우스 터치·드래그·스크롤·뒤로가기/재진입은 수행하지 못했다. 현 실행의 터치 진단은 down/move/up/cancel/measured 모두 0이며 이를 PASS로 표시하지 않는다.

다크 상태바 대비, 큰 글씨의 잘림/스크롤, Reduce Motion 정지, Reduce Transparency 불투명 fallback 확인을 위해 각 설정을 일시 전환하고 원래대로 복원하는 검증 허용을 요청했다. 응답 전에는 변경하지 않았다. 현재 진단은 lowPowerMode/reducedMotion/reducedTransparency=false였다. 권한/보안/인증 설정을 변경하지 않았다.

남은 최소 사용자 동작: iPhone 잠금 후 미러링 연결을 허용할 수 있도록 잠시 사용 중단, 위 네 설정의 일시 전환·원상복원 검증 허용 여부 전달. 그 전까지 전체 디자인 실기기 PASS는 아니다. 이전 가독성·레이아웃 사용자 승인은 해당 기존 범위만 유지한다.

개인 위치/알림이 포함된 원본 캡처와 기기/설치 로그는 Git 밖 `evidence/snow-guidance-device-20261010`에 보관했다. 이번 수정은 미커밋 상태이며 푸시·main 병합·배포하지 않았다. 임시 build workspace/project와 의존성 연결만 정리하고 원래 보관본·사용자 데이터는 유지했다.

## 사용자 잠금 후 미러링 재검증

사용자가 iPhone 잠금을 완료한 뒤 같은 설치본으로 CUA iPhone Mirroring 연결을 다시 확인했다. 이번에는 잠금 대기 화면이 아니라 실제 Home 전체가 표시됐고 캡처가 가능했다. 창 AX에는 일반 미러링 툴바만 표시돼 앱 내부 버튼은 좌표 기반 입력이 필요했다.

현재 라이트 홈의 작은 날씨 아이콘, 대표 준비 카피/시각, 목적지 glass, 코디 톤 표면, 하단 glass를 가림 없이 확인했다. 시간차 스크린샷 사이에 확산 띠의 위치/밝기 변화는 보이지만 연속 영상/idle 자연스러움 PASS로 판정하지 않는다. 미러링의 회색 포인터 효과를 앱 국소 터치 빛의 증거로 사용하지 않았다.

## 사용자의 강수 예보 직접 클릭 후 확인 제한

사용자가 Mac 미러링에서 강수 예보를 직접 눌렀다고 전달했다. 이번 확인은 사용자 조작에 따른 화면을 읽는 작업이며 자동 클릭 성공으로 기록하지 않는다. CUA AX는 미러링 툴바/메뉴만 반환했고 앱 내부 텍스트를 노출하지 않았다. 화면 캡처는 기울어진 작은 썸네일로 반환됐다. Mac 미러링의 보기 → 확대를 일시 시도했으나 JPEG 원본 해상도 자체가 74×220으로, 목적지/선택 시각/오래됨/예보 부재 문구를 판독할 수 없었다. 보기 → 실제 크기로 원래 창 표시를 복원하고 확인용 메뉴를 닫았다. iPhone 테마·글씨·접근성 설정은 변경하지 않았다.

대체 읽기 전용 devicectl 원본 캡처는 미러링 중인 iPhone 잠금 화면을 반환했다. 이것은 미러링 앱 콘텐츠의 캡처가 아니므로 H5의 증거로 사용하지 않는다. 확대·창 Raise로도 읽을 수 있는 본문을 확보하지 못해 H5 실제 표시/위치·시각 일치/빈 예보·stale/가독성/복귀는 아직 확인 불가다. 이전 홈에서 선택 시각이 표시됐다는 사실만으로 H5 전달 성공을 추정하지 않았다.

다음 최소 동작은 Mac에서 미러링 본창을 전면에 표시해 강수 예보 화면을 읽을 수 있게 유지하는 것이다. 필요 시 해당 화면 스크린샷을 제공받아 위치·시각을 확인한 뒤 뒤로가기를 검증한다. 이번에도 앱 소스·사용자 일정/위치/알림·설정 변경, 빌드·설치·커밋·푸시는 없다.

## 재확인: H5 화면·자동 탐색 성공

사용자가 다시 확인을 요청한 뒤 CUA 미러링 캡처가 읽을 수 있는 전체 크기로 복구됐다. 첫 화면은 사용자가 직접 연 H5였다. 이전 축소 캡처 실패 기록과 구분한다. H5 제목은 강수 예보이며 부제 목적지가 이전 Home의 선택 목적지와 일치했다. 홈의 `목적지 도착 무렵 · 10/11 10:00`과 H5의 `도착 기준 · 10/11 10:00`이 일치했다. 개인 목적지 이름은 문서에 옮기지 않았다.

표시 구간은 10/11 10:00–18:00, 행은 10:00부터 17:00까지 8개이며 각 행은 0%·0mm였다. 홈의 최대 0% 요약과 일치한다. 제목은 확인된 시간대의 강수 신호가 낮다는 표현이고, 이후 비 그침은 확인되지 않았다는 하단 안내가 표시됐다. 현재 화면에는 예보 부재/일부 시간 누락/최근 기준·최신 확인 필요 상태가 표시되지 않았다. 이는 정상 데이터 분기의 관찰이며 누락·stale 분기를 실제 기기에서 시험했다는 의미는 아니다. 공급자 원본 수치의 외부 독립 검증도 아니다.

이후 CUA 좌표 클릭으로 H5 뒤로가기 → Home → 강수 예보 재진입 → H5 → 뒤로가기 → Home을 수행했다. 이번에는 noWindowsAvailable 오류 없이 실제 화면 이동을 확인했다. 첫 재진입 캡처가 네이티브 전환 도중이라 정착 후 다시 캡처해 전체 문구·행·문맥을 확인했다. 재진입에도 같은 목적지/선택 시각/예보 구간이 유지됐다. 최종 화면은 Home이다.

H5의 제목, 기준 시각, 시간별 확률/양, 설명에서 잘림·겹침은 보이지 않았다. 현재 라이트/기존 글씨 배율에 한정한 정지 화면 가독성 관찰이다. 표시된 알림 스위치는 누르지 않았으며 현재값을 바꾸거나 알림을 발송하지 않았다. 앱 일정·위치·테마·접근성 설정 변경, 빌드·설치·커밋·푸시는 없었다.

이제 H5 왕복·재진입과 해당 정상 분기의 위치/시각 전달은 실기기 탐색 증거가 있다. 탭 왕복·국소 누름/이동/해제·연속 스크롤·idle 자연스러움·다크/큰 글씨/접근성 전체 PASS로 확대하지 않는다. 근거는 이번 CUA의 읽을 수 있는 원본 H5/Home 스크린샷 및 성공한 클릭 응답이다.


## 현재 모드 실제 입력·탭 왕복 후속 검증

기기 설정을 유지하고 기존 설치본에 CUA 입력을 수행했다. 빈 배경에 2,500ms 누름을 요청하고 해제, 같은 빈 영역에서 수평 드래그 1회, 아래 방향 스크롤 1회, 코디 탭 → Home 왕복 1회를 실행했다. 사용자 데이터·알림·설정 변경이나 새 빌드/설치/코드 수정/커밋/푸시는 없다. 최종 화면은 Home이다.

- 누름/드래그 전 진단은 down=2, move=0, up=2, cancel=0, measured=2였다. 두 동작 뒤에는 down=4, move=1, up=4, cancel=0, measured=4, phase=up으로 바뀌어 입력 도달과 해제를 확인했다. 드래그 도구는 속도를 지정하지 못하므로 천천히 손가락으로 이동한 체감 검증으로 간주하지 않는다.
- 누름 요청 시작 후 캡처 시점은 123ms, 3,925ms, 3,983ms였다. 첫 프레임은 입력 Promise 완료 전이지만 포인터가 아직 이전 위치여서 실제 눌린 중간 프레임으로 확정할 수 없다. 뒤 두 프레임은 해제 뒤다. 연속 누름 반응·부드러운 복귀는 이 시퀀스만으로 PASS하지 않는다. 회색 포인터 후광은 미러링 효과로 앱 효과 증거에서 제외했다.
- 스크롤 직후 콘텐츠가 약 48 이미지 픽셀 위로 이동하며 로고 위쪽이 뷰 경계에 일부 가려졌다. 후속 캡처에서는 원래 위치와 전체 로고가 복구됐다. 배경과 하단 dock은 두 프레임에 계속 표시됐다. 기존 진단 viewport/content=758/758pt, overflow=0인 현재 조건의 일시 이동/복귀 관찰이며, 긴 콘텐츠의 지속 스크롤 검증은 아니다. 캡처 사이 짧은 플래시의 부재까지 보장하지 않는다.
- 코디 선택과 Home 복귀를 실제 화면으로 확인했다. Home 복귀 직후와 약 23,075ms 뒤 캡처에서 광선 띠의 위치/강도 변화가 보였고 배경은 유지됐다. idle의 시간차 변화 근거는 확보했으나 연속 영상의 자연스러움·프레임 안정성 PASS와 구분한다.
- Home 복귀 뒤에도 기온 옆 작은 아이콘/체감/최고최저, 준비 카피와 여백, 목적지 glass, 코디의 옅은 표면/이미지, 하단 glass가 유지됐다. 현재 라이트·기존 글씨 배율의 관찰 프레임에서 본문 잘림/겹침/가독성 저하는 보이지 않았다. 미러링 화면은 시스템 상태바를 포함하지 않아 이번 상호작용으로 상태바 대비를 재검증했다고 하지 않는다.
- 탭 왕복 후 진단 파일은 phase=policy, 카운터 모두 0이었다. 따라서 이를 앞선 실제 입력의 누락으로 해석하거나 전체 세션 합계로 사용하지 않는다. lowPowerMode/reducedMotion/reducedTransparency=false가 유지됐다.

추가 관찰: 코디 탭 상단에는 `23도 · 맑음 · 오늘 몸이 느낄 날씨 기준`과 `비 소식 있어요. 우산과 방수 신발 챙겨요`가 함께 표시됐다. 같은 왕복의 Home에는 맑음과 목적지 최대 강수확률 0%가 표시됐다. 서로 다른 기준/데이터가 원인인지는 조사하지 않았으며 회귀나 원인을 단정하지 않는다. 다른 화면 수정 금지 범위를 지켜 관찰만 기록했다.

근거는 이번 CUA 입력 결과/원본 시퀀스 캡처와 Git 밖 evidence의 `weatheron-interaction-before.json`, `weatheron-interaction-after-drag.json`, `weatheron-interaction-final.json`이다. 다크·큰 글씨·Reduce Motion/Transparency, 느린 직접 드래그·연속 영상 체감은 여전히 미검증이다.
