# iOS Home Ambient Surface 빛·깊이 보정 — 2026-10-10

## 범위와 기준

승인된 홈 정보/레이아웃/실제 날씨/공통 테마 동작을 유지하며 기존 Ambient Surface의 빛 확산·그레인·느린 흐름·국소 터치 복귀만 보정했다. 새 효과·의존성·API·권한·서명 변경은 없으며 Android나 다른 화면을 개발하지 않았다. 커밋·푸시·배포는 하지 않았다.

기준은 `docs/design/ambient-surface-pages-20261009/WeatherON-01A-Core-Weather-20261009/images/01-core-ios-light-v3.png`, 같은 폴더의 `01-core-ios-dark-v3.png`, Project Wind의 `yokohama_tower_of_winds_ui_design_system.md` §1/6/10 및 perfora 방향·컴포넌트 문서다. 정적 레퍼런스의 비 예시를 현재 맑은 날씨에 복사하지 않았다. 레퍼런스 대비 텍스처와 공간감의 완전한 일치는 확인되지 않았다.

## 변경

- 기존 두 radial field의 좁은 밝은 경계와 넓은 확산을 분리하고, 큰 타원 중심을 화면 밖으로 옮겨 홈의 빈 공간에도 곡면이 나타나도록 조정했다. 기존 35–44초 공통 시계와 계절/날씨 흐름은 유지했다.
- 라이트 바탕의 색 전이를 부드럽게 만들고, 기존 네이티브 그레인의 alpha 분포를 조정해 흰 막의 평균은 낮추고 미세 변동은 살렸다. 텍스처는 레이아웃/테마 시점에 utility queue에서 생성되며 프레임마다 Core Image를 실행하지 않는다.
- 동일한 국소 터치 영역을 타원형 확산으로 바꾸고 복귀를 620ms sine easing으로 조정했다. 기존 native driver, 읽기 보호, 스크롤 취소와 공통 위상은 유지했다.
- 기존 DEBUG 진단 경로에 텍스처 크기/생성 시간/thermal 숫자만 추가했다. 위치·계정·터치 좌표·날씨 내용은 기록하지 않는다.

## 테마 회귀와 복구

검증 도중 개발용 다크 미리보기를 홈 본문에만 적용해 라이트 시스템에서 헤더/탭과 본문이 섞이는 문제가 발생했다. 이는 이 작업에서 넣은 테스트 override의 오류이며 사용자 설정 때문이 아니다. 사용자 피드백 이후 JS state/prop 및 native launch-argument 처리 전체를 제거했다. 최종 Home은 기존 `ambientHomeTheme(useAppTheme(), Platform.OS === "ios")`만 사용한다. 설정 저장값은 변경하지 않았다. 실제 위치·시간에 의한 낮/밤 판단은 테마와 독립적이다.

최종 소스로 다시 빌드·설치하고 테스트 인자 없이 실행했다. 정상 홈 전체 캡처에서 상단·본문·탭 모두 라이트인 것을 확인했다. 공통 공급자 사용 및 임시 override 금지 회귀 검사를 추가해 통과했다. 초기 후보의 다크 미리보기 캡처는 최종 다크 실기기 QA 통과 증거가 아니다.

## 검사와 설치 증거

소스가 각각 다른 후보를 세 차례 순차 증분 빌드했다: 초기 보정, 곡면 위치/진단 보정, 임시 테마 override 제거. 동일 소스 반복 빌드나 병렬 빌드는 하지 않았다. Xcode 27, 기존 derived data와 QA workspace, ARM64/jobs1 조건으로 최종 `BUILD SUCCEEDED`, 서명 검증 및 iPhone 설치·정상 실행 성공. 앱 삭제/설정 초기화 없이 설치했다.

최종 설치 실행 파일 SHA-256: `f283c0180b293f9d46bd3919a997e78b82af377e0e4490732c5e7d420ff002a9`.

타입 검사, Ambient response/surface 회귀, Home 목적지·강수·체감·SQLite·내비게이션·JSX 회귀, 공통 테마 guard 및 whitespace 검사 통과. 밤/구름/비/눈과 Reduce Motion/Transparency/low-power 경로는 컴포넌트/fixture 검사이며 실제 설정 전환의 체감 통과를 의미하지 않는다. 초기 다크 강도 증가는 muted 대비 4.43:1로 실패해 되돌렸고, 최종 보수적 최저값은 dark/clear text 6.93:1, muted 4.57:1; light text 12.52:1, muted 5.37:1이다.

기기 텍스처 진단은 512×918 생성 이미지, 560×918 뷰, 생성 66.10ms, thermalState 0(단일 정상 스냅샷)을 기록했다. 이는 이미지 할당/크기가 유효하다는 증거이며 FPS나 장시간 발열 보장이 아니다. 최종 레이아웃 수치는 viewport/content 758/758, fontScale 0.882, overflow 0이다.

정상 라이트 전체 캡처에서 열린 바탕의 곡선 확산과 기존 홈 레이아웃을 확인했다. 최종 연속 캡처 중 기기가 다른 화면으로 이동한 프레임은 idle 픽셀 비교에서 제외했다. 따라서 최종 연속 움직임 개선 수치는 보고하지 않는다. 기존 pixel 비교와 Mac Core Image harness 결과도 실기기 연속 체감 증거로 사용하지 않는다.

기기 진단에는 down 2/move 33/up 2 및 end-received가 기록되었다. 사용자 기기 사용이 섞여 있어 이 숫자만으로 국소 반응의 눈에 보이는 강도/복귀나 스크롤 연속성의 통과를 판정하지 않는다.

## 남은 확인

실기기 화면 녹화 명령은 해당 기기에서 지원되지 않았고, iPhone Mirroring은 사용 중/잠금 필요 상태여서 자동 물리 입력을 수행하지 않았다. 사용자 화면에 추가 테스트 모드를 적용하지 않았다.

1. 정상 홈을 10–15초 보며 확산/그레인/깊이가 읽기를 방해하지 않고 느린 흐름이 느껴지는지 확인.
2. 빈 바탕을 눌러 이동·놓기와 스크롤을 연속해 국소 빛 복귀와 흐름 연결을 확인.

최종 다크 실기기, 접근성/저전력 실제 전환, 장시간 발열·프레임 안정성 및 이전 전체 하늘/유성/터치 사용자 체감은 미검증 상태를 유지한다. 이전 실패/미검증을 통과로 바꾸지 않았다.

원본 캡처·로그는 Git 밖의 로컬 evidence에만 보존했다. 위치/계정/연락처가 포함된 원본 픽셀과 기기 식별자·로컬 절대 경로는 공유 문서에 포함하지 않았다.
