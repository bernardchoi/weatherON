# iOS 코디의 오늘 범위·최신성 수정

## 승인 범위와 원인

사용자의 코디 시간 범위 및 오래된 데이터 표시 수정 승인에 따른 작업이다. 기존 홈 눈 안내 미커밋 변경을 보존했다. 공유 recommendOutfit은 현재와 전체 hourly의 최대 강수 신호를 사용했지만 코디 UI는 오늘 기준이라고 표시했다. 현재 맑음과 이후 비의 공존 자체는 오류가 아니다. 실제 관찰 당시 강수 원본 시각·수치는 확보하지 못해 그 화면의 개별 강수 원인은 확정하지 않는다.

수정 전 실제 공유 함수에 현지 23:30 / 다음 날 00시 강수만 넣은 최소 재현이 `Tomorrow rain must not drive today outfit` assertion에서 실패했으며 실제 문구는 비 소식/우산이었다.

## 구현

- `utils/todayOutfit.ts`: 선택 snapshot의 명시적 유효 IANA 시간대를 사용해 현재 진행 중인 시간부터 다음 현지 자정 전까지 제한한다. 종료한 과거 interval과 다음 날 예보를 제외한다. 날짜 없는 HH:mm은 날짜를 추론하지 않는다. 기기 시간대로 대체하지 않는다.
- iOS 앱 state에서만 제한된 snapshot으로 의류 추천을 다시 계산한다. 기존 shared rule, Android, 위젯/알림 계산을 바꾸지 않는다. state의 원본 weather와 목적지/H5 자료도 유지한다.
- current 확률·양이 공급자 첫 hourly에서 유래할 수 있어 현재 포함 interval의 값으로 다시 정한다. 현재 condition과 이후 시간별 강수 문구를 구분한다.
- 오늘 남은 시간의 연속 예보 coverage와 값/WeatherKit 필드 존재를 검사한다. 시간대 불명, 예보 없음·일부 누락에는 확인 필요를 표시한다. 누락을 비 없음으로 처리하지 않는다.
- stale/cache/fallback/미확인 위치 또는 15분 경과 자료는 최신 코디 안내를 중단하고 최근 자료 표시를 한다. 관측 시각은 예보 대상 시각과 별도로 위치 시간대에 표시한다. fallback/미확인 위치/유효하지 않은 관측 시각에는 관측값·시각을 제시하지 않는다.
- 코디 목록과 상세에 같은 기준 안내를 표시하며 상세의 확률 집계도 오늘 범위로 맞춘다. 미확인 구간은 비 없음 대신 예보 확인 필요로 표시한다. 홈 레이아웃·아이콘·Glass·배경 소스는 수정하지 않았다.

## 코드 검사

`node scripts/check-today-outfit.mjs` PASS: 현지 자정, 과거/다음 날 강수 제외, 현재 맑음+오늘 이후 비 보존, 오래된 관측/stale/cache/미확인 위치, 예보 없음/필드 누락/coverage gap, 명시 시간대 부재·오류, UTC와 뉴욕 날짜 차이, DST 시작/종료 경계, 관측 시각과 대상 시각 구분.

기존 `check-home-outing.mjs`(눈/불명확 강수상/현재·미래 구분 포함), `check-weather-outfit-regressions.mjs`, `check-ambient-surface-regressions.mjs`, `check-home-viewport.mjs` PASS. 모바일 tsc --noEmit PASS, 번역 검사 2168 messages PASS, git diff --check PASS. 테스트 fixture는 공개 가상 위치·고정 시각이며 기기에 주입하지 않았다.

## 실기기 관찰

기존 라이트/글씨/접근성 설정에서 정상 실행 Home의 작은 보조 아이콘·체감/최고최저·준비 카피·목적지 Glass·옅은 코디 표면/이미지·하단 Glass를 확인했다. 실제 데이터는 현재 흐림으로 바뀌었다. 코디 화면에서 현재 22도·흐림, 오늘 남은 시간 기준, 관측 10/10 18:09, 오늘은 가볍게 편한 차림 안내와 변경된 추천 의류가 표시됐다. 읽을 수 있는 전체 프레임에서 문구 잘림/겹침이 없었다. 현재 화면은 정상 최신 분기이며 stale/예보 누락/이후 강수 분기의 실기기 날씨 주입 검증은 아니다.

초기 탭 전환 캡처에 Home과 코디가 겹쳤고 후속 재조회에서 정상 코디 화면이 확보됐다. 그 뒤 코디 자세히 보기/의류 클릭은 상세 진입을 화면으로 확정하지 못했고, 홈 탭 선택 후에도 코디 내용이 남는 프레임이 있었다. 앱과 미러링 중 어느 층의 현상인지 단정하지 않는다. 전체 탐색 PASS는 보류한다.


### 동일 설치본 재실행 후 탐색 확인

같은 앱을 데이터 삭제 없이 정상 재실행 1회 했다. 새 빌드/재설치는 없다. Home 정상 표시 후 코디 목록 → 코디 상세 → 뒤로가기 → Home을 실제 CUA 입력으로 확인했다. 코디와 상세 모두 오늘 남은 시간 기준 및 관측 10/10 18:12가 일치했고, 상세의 18/19/20시 카드가 표시됐다. 네이티브 슬라이드 전환 중 프레임과 정착 프레임을 구분했으며, 정착 화면은 중첩/잘림 없이 읽혔다. 최종 Home도 정상 표시됐다. 앞선 중첩의 원인을 앱 또는 미러링으로 확정하지 않으며, 그 기록을 삭제하지 않는다.

재실행 후 후속 코디·상세·Home은 다크 색상으로 표시됐다. 이번 작업은 테마/접근성 설정 UI를 열거나 변경하지 않았고 코드에도 dark override를 추가하지 않았다. 색상 변경의 원인을 추정하지 않는다. 두 색상의 실제 관찰 프레임은 있으나 의도적으로 설정을 왕복한 전체 다크/접근성 QA로 간주하지 않는다.

연결 끊김 알림 후에도 Mac 명령 실행·CUA가 동작하고 저장된 변경이 유지됨을 확인했다. 진행 중 xcodebuild/Metro 프로세스가 없었으며 중복 빌드는 하지 않았다. 현 범위의 구현·코드 검사·빌드·설치·정상 데이터 화면 탐색은 완료됐다. stale/시간대 불명/예보 누락/오늘 이후 강수는 자동 회귀 근거이며 기기 설정/날씨를 강제로 바꿔 실기기 PASS를 만들지 않았다. 저장·알림·계정·목적지 데이터 변경 버튼을 누르지 않았다.


## 초기 중첩 추가 조사 — 원인·해결 미확정

현재 설치본과 기존 실행 세션을 확인한 뒤 Home → 코디 → 상세 → 뒤로가기 → Home 1회, 동일 설치본 일반 재실행 후 같은 왕복 1회를 검증했다. 추가 소스 수정·빌드·설치는 없다. 최종 Home 정상 표시, 사용자 설정/데이터는 변경하지 않았다.

기존 세션 상세 클릭 요청 시작 약 936ms 뒤 프레임에는 상세가 오른쪽에서 들어오고 왼쪽에 목록 일부가 남았다. 약 8,346ms 뒤에는 상세가 전체 너비로 정착했다. 이 숫자는 도구 요청/관찰 시각이며 애니메이션 지속 시간이나 앱 프레임률 측정값이 아니다. 코드의 NavigationStack.tsx:47은 상세에는 default 네이티브 전환을, backRoute 없는 탭 이동에는 none을 사용한다. 따라서 이번 상세 진입 중 옆 화면 노출은 슬라이드 전환의 근거가 있지만, 이전 Home 본문이 코디 위에 오래 남은 현상까지 같은 원인으로 설명하지 않는다.

일반 재실행 첫 관찰은 브랜드 스플래시와 하단 개발 경고였고 7,874ms 뒤 관찰은 Home과 하단 경고였다. 경고 닫기 후 첫 코디 클릭 요청 약 977ms 뒤에는 중첩 없는 코디가 표시됐다. 이어 상세 정착 및 홈 복귀도 정상이다. 최초 문제 당시의 경고 닫기 → 첫 탭 이동 경로를 반복했으나 지속 중첩은 재현되지 않았다. 현재 관찰은 다크이며 최초 현상은 라이트였다. 설정을 바꾸어 억지로 동일 조건을 만들지 않았다.

개발 경고의 기존 진단 분류는 existing-app-attest-assertion 1회였다. 경고 막대는 하단에만 보이고 스플래시는 브랜드 로고 화면이다. 둘 모두 초기 문제의 겹친 Home 본문/목적지 패널과 다른 픽셀 내용이다. 경고를 숨겨 중첩이 해결됐다고 하지 않는다.

이번 코디 수정의 diff에는 NavigationStack, AppNavigator, HomeAmbientHost, LaunchSplash 변경이 없다. 실제 reconcileScreenStack 함수를 추출해 Home/Codi/detail/back/Home 100회 반복한 논리 스택 검사는 PASS이며 탭 교체 후 Home+Codi가 함께 남지 않는다. 이는 UIKit 실제 view 계층/프레임 버퍼의 잔류를 배제하는 검사는 아니다. 기존 check-native-navigation 전체 스크립트는 별도 정책 화면 테스트의 policyDocumentReturnRoute mock 누락 ReferenceError로 중단되므로 전체 PASS로 기록하지 않는다. 해당 부분 이전 검사와 이번 경로 반복만 통과했다.

결론: 이번 추가 시도에서는 지속 중첩 미재현. 독립적인 동시 iPhone 화면/네이티브 view 계층 근거가 없어 앱의 네이티브 화면 잔류인지 미러링의 이전 합성 프레임인지 구분하지 못했다. 과거 미러링의 사용자 변경/연결 불안정 응답은 원인 가능성의 맥락일 뿐 증명이 아니다. 원인이 확인된 수정은 없으며 해결 완료로 판정하지 않는다. 최초 설치 직후의 상태와 지금 정상 재실행 상태가 같다는 보장도 없다. 재발 시 같은 순간의 앱 네이티브 표시와 미러링 표시/route를 대조해야 한다. 추정 원인으로 디자인·네비게이션을 변경하지 않았다.


## 공식 기기 디스플레이 캡처 추가 대조

공식 devicectl display 조회에서 Wireless 디스플레이를 발견했고 이를 지정한 screenshot으로 앱 픽셀을 확보했다. LCD 잠금화면 캡처 한계만으로 직접 캡처가 불가능하다고 판단하지 않는다. Wireless는 Mac 창 합성 이전 기기 측 디스플레이 근거지만 실제 LCD나 UIKit view 계층 덤프는 아니다. 공식 screen-record는 CoreDeviceError 1001 / Screen Recording 미지원으로 실패했고 동영상은 생성되지 않았다. 권한 확대나 우회는 하지 않았다.

일반 재실행/첫 탭 이동 구간에 3초 간격 공식 캡처 12장을 확보했다. 05는 Home+하단 개발 경고, 10·11은 정상 코디였다. 10번 요청 구간(1791624415849–1791624417024ms)에 Mac 관찰(1791624416277ms)이 포함되며 두 화면은 같은 관측 시각·내용의 코디였다. 정확한 픽셀 취득 시각까지 동기화한 측정은 아니다. 11번이 비어 보인다는 중간 판독은 원본 재확인에서 정상 본문이 확인되어 정정한다. 별도 정착 상세 캡처도 Mac 상세와 일치했다.

추가 목록 복귀 후 weatheron-native-codi-stable.png는 앱 영역의 단색 배경만 담겼다. 직전·직후 Mac 관찰은 정상 코디였고, 입력 없는 재캡처 weatheron-native-codi-repeat.png에는 정상 코디와 내비게이션이 다시 담겼다. 이 단일 빈 캡처를 사용자에게 보인 지속 빈 화면이나 초기 Home/Codi 중첩의 재현으로 판정하지 않는다. 기기 측 캡처도 순간 합성 상태를 놓칠 수 있으며 연속 영상/동시 route 기록 없이 원인을 확정할 수 없다.

초기 복원 route는 O1에서 시작하고 hydration 완료 시 H1/O1로 정하며 코디/상세 스택을 복원하지 않는다. hydration effect는 storageRetryTick 의존성과 cleanup active guard를 가진다. 실기기 Debug AppDelegate는 내장 main.jsbundle을 사용하고 Metro URL은 simulator 조건이다. 루트 중복 등록이나 개발 reload를 원인으로 뒷받침하는 증거는 없다. UIKit 수명주기 문제까지 배제하지 않는다.

이번 조사는 앱 코드·빌드·설치를 추가 변경하지 않았고 기존 미커밋 수정 전부를 보존했다. 최종 Home 복귀 정상. 초기 지속 중첩의 원인과 해결은 미확정이다. 연속 실기기 증거가 필요하면 사용자가 iPhone 자체 화면 기록으로 앱 열기 → Home → 코디 → 상세 → 뒤로가기 약 20–30초를 기록하는 것이 남은 최소 추가 입력이다. 현재 접근으로 공식 기기 녹화는 미지원이다. 원본과 타이밍은 Git 밖 evidence/outfit-day-scope-20261010/native-display-comparison에 보관했다.
