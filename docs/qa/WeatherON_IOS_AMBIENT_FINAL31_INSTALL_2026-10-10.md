## O4 원인 분리 이력 — 사용자 직접 확인 전 진단

추가 수정 승인 후 높이/입력 경로를 실측했다. JS에서 shell 758pt, ScrollView viewport 약 589–614pt(임시 측정 텍스트 줄바꿈 때문에 변동), content 1028pt, offset 0이 관찰됐다. UIKit 직접 측정도 frame/bounds 높이 589 또는 614.33pt, content 1028pt이며 isScrollEnabled=true, panGestureRecognizer.isEnabled=true, alwaysBounceVertical=true였다. 터치 시작/이동 이벤트가 본문 ScrollView에 도달했고, 중앙 hit-test 조상 계층에도 RCTEnhancedScrollView가 포함됐다. 그러므로 높이 제한 누락, 콘텐츠 높이 0, 스크롤 비활성, 터치가 전혀 도달하지 않는 덮개로 단정할 근거는 없다.

- 디버거 직접 연결은 LLDB 시스템 이미지 로딩 중 종료되어 사용하지 못했다.
- JS 콘솔은 기기 console 스트림에 전달되지 않아 임시 화면 표시로 측정했다.
- UIKit 기하 정보만 임시 출력해 교차 확인했다. 사용자 텍스트/사진/계정 데이터는 로그 대상에 포함하지 않았다.
- 고정 footer 화면의 shell collapsable=false를 한 변수로 시험했으나 미러링 스크롤은 동일했다. 해당 변경을 제거했다.

- 두 후보 모두 빌드/설치는 성공했지만 자동 입력 현상에 효과가 없어 채택하지 않았다. 진단 코드는 AppScreen 및 Swift 양쪽에서 제거하고 최초 파일과 일치함을 확인했다.
