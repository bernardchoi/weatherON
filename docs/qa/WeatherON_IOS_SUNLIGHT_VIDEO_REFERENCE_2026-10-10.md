# iOS Home 햇빛 효과 — 첨부 영상 확인 및 구현 2026-10-10

## 실제 참조 확인

사용자가 첨부한 `ScreenRecording_10-10-2026 12-46-34_1.MP4`를 공식 Library 경로로 소비자 Mac에 저장하고 AVFoundation으로 0/1/2/3/4/5/6초의 원본 프레임을 실제 열어 확인했다. 파일은 8,074,504바이트, 길이 6.615011초, HEVC 1320×2868, 트랙 nominal frame rate 약 58.507이다. SHA256: `ee873f3d5b05249786c4b857ffe0c5e843eb0d07c66cff0da8aaf9e58dbafc95`.

초반 도시 전환은 레이아웃/날씨와 밝기를 함께 바꾼다. 이를 idle 반복으로 해석하지 않았다. 후반 3–6초의 안정 구간에서 상단에 걸친 밝은 광원과 넓은 halo, 아래쪽으로 퍼지는 옅은 빛, 느리게 위치·밝기가 변하는 렌즈 번짐을 관찰했다. 짧은 영상만으로 전체 주기 길이/정확한 속도/측정된 태양 각도를 단정하지 않았다.

## 구현

`AmbientWeatherLayer.tsx`의 기존 전체 하늘 sunlight field를 자체 작성한 광원·halo·두 soft ray 그라데이션으로 조정했다. Apple 영상의 픽셀/애셋을 추출해 앱에 복제하지 않았다. 원본 영상/프레임도 앱 리소스나 Git에 넣지 않았다.

상단 오른쪽에 걸치는 광원을 기존 Home 브랜드 바탕에 맞춰 표현한다. 동일 공통 native phase에서 작은 평행 이동, 회전(-1.2~0.8도), 밝기 변화를 연결한다. 별도 타이머/새 의존성은 없다. 경계는 모두 투명으로 끝나고 measured sky를 overscan해 네모 패널 경계를 방지한다. 확정된 레이아웃/작은 상태 아이콘/준비 문구/실제 목적지 자료는 그대로다.

실제 신뢰 가능한 맑은 날씨 + 실제 태양 시간의 day/twilight에서만 표시한다. UI 테마는 표시 강도만 바꾸며 밤 여부를 만들지 않는다. 밤/흐림/비/눈에서는 햇빛을 넣지 않는다. Reduce Motion/저전력/비활성에서는 기존 공통 phase를 멈추고, Reduce Transparency에서는 기존 효과 생략 경로를 유지한다. 권한/인증/서명/설정 저장값/Android/다른 화면 변경은 없다.

## 긴급 테마 복구

이전 Ambient 검증에서 추가한 홈 본문 전용 다크 미리보기 때문에 시스템 라이트와 헤더·탭/본문이 섞였었다. 그 override의 JS/native 코드 전체를 제거한 뒤 정상 설치 캡처로 복원했다. 이번 영상 작업에서는 새 테마/날씨 미리보기나 launch override를 추가하지 않았다. 최종 Home은 공통 테마 공급자만 사용한다.

## 검증과 설치

- 타입 검사, Ambient response/surface 회귀, 실제 RN gradient parser, 태양시간/UI theme 분리 및 night/non-clear 햇빛 생략 검사, Home/아이콘 회귀, whitespace 검사 통과.
- 기존 response 검사에 있던 이전 72% 문자열 가정은 새 100% 투명 끝점 표현에 맞춰 갱신했다. 처음 검사 실패를 무시하지 않고 실제 RN 파서의 모든 layer 투명 falloff 검사와 함께 다시 통과했다.
- 보수적 dark/clear 최소 대비: 본문 6.97:1, muted 4.59:1, accentLabel 5.16:1. 원본 영상처럼 강한 흰 빛을 dark UI에 그대로 쓰지 않았다.
- 최초 구현 및 상단 위치/숫자 진단 보정의 서로 다른 소스를 두 번 순차 증분 빌드했다. 최종 Xcode 27 ARM64/jobs1 `BUILD SUCCEEDED`, 서명 검증·iPhone 설치·테스트 인자 없는 정상 홈 실행 성공. 삭제/설정 초기화/클라우드 빌드/배포는 하지 않았다.
- 최종 설치 JS bundle SHA256: `6cc911699e9ac00722aaa6ac234a0e79ae058ce78cfc1fb2110309c8ceb002aa`.
- 실제 설치 진단은 reliable=1, clear=1, solarPhase=3(day)이다. 위치 좌표/계정/날씨 payload 없이 조건 숫자만 기록한다. 기존 정책 진단은 lowPower/reducedMotion/reducedTransparency=false였다.
- 최종 정상 홈 전체 프레임에서 상단의 따뜻한 확산, 라이트 상단/본문/탭 일치, 작은 날씨 아이콘, 네모 광원 경계가 없는 것을 확인했다. 기존 레이아웃 진단은 viewport/content=758/758, fontScale=.882, overflow=0.
- 서로 17.835초 떨어진 실제 1320×2868 홈 PNG의 글자·아이콘·사진·glass·시스템 UI를 제외한 영역을 비교했다. 상단 빛 ROI의 평균 RGB 채널 차이는 6.312, 열린 오른쪽 바탕은 6.191이다. 두 프레임에서 native background가 실제 변한 증거이며 공통 base와 햇빛 각각의 기여를 분리하거나 연속 체감/부드러움의 통과를 증명하지 않는다.

첫 설치 캡처에 기존 App Attest assertion 분류 경고가 나타났다. 경고 전달을 유지했으며 인증정보/설정 변경 또는 경고 숨김 처리를 하지 않았다. 후속 정상 프레임에는 toast가 사라졌다. 이는 경고 자체 해결의 증거가 아니다.

## 남은 사용자 QA

햇빛은 밝은 브랜드 바탕에 맞춘 절제된 강도다. Apple 영상처럼 빛이 뚜렷하게 느껴지는지, 10–15초의 연속 움직임이 자연스러운지, 터치·스크롤 복귀가 방해 없이 이어지는지는 사용자 실기기 체감 확인이 필요하다. 화면 녹화는 앞선 시도에서 해당 기기의 지원 불가를 확인했으므로 반복하지 않았다. 최종 dark/접근성/저전력 실제 전환과 장시간 FPS·발열은 미검증이다. 이전 밤·유성·터치 실패/미검증은 통과로 바꾸지 않았다.

원본 영상·프레임·전체 캡처·로그는 Git 밖의 로컬 evidence에만 보존했다. 로컬 절대 경로/기기 식별자/위치·계정·연락처 원본 픽셀은 이 공유 문서에 넣지 않았다. 커밋·푸시는 하지 않았다.
